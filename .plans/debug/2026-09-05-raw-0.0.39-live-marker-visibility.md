# Raw 0.0.39 live marker visibility diagnosis

**Date:** 2026-09-05  
**Bead:** `aerobeat-web-assembly-vm4`  
**Research:** `dc1240d2-2243-4ea5-935b-0ba7aa4310e6`  
**Candidate:** immutable raw `0.0.39`  
**Disposition:** Diagnosis complete; no alpha/depth bypass is authorized. Await consolidated repair-plan approval.

## Exact Observed Failure

During live-camera Flow gameplay, Derrick reports that the nose and wrist 3D landmarks appear transparent and are hard to see. Shader or z-fighting was suspected.

The exact runtime marker is visible at the requested `18 CSS px`, but its intended dark/white/tint structure collapses at that footprint and appears mostly bright over live video.

## Expected Behavior

Markers must remain visibly solid and distinguishable over bright, dark, skin-tone, blue, green, and high-frequency camera imagery while preserving:

- measured normalized X/Y and truthful world Z `0.45`;
- opaque alpha, back-face culling, depth test/write, and truthful occlusion;
- white/charcoal structure with only `mat/tint_base` role-tinted;
- deterministic CSS-size contract, pooling, context restore, disconnect/reconnect, and privacy.

## Execution Path

1. Assembly projects accepted nose/wrist evidence and requests `sizeCssPx:18`.
2. Renderer maps normalized coordinates into the gameplay grid and computes a world scale that yields approximately 18 CSS px in portrait and landscape.
3. Marker `0.0.7` loads three materials: charcoal, white, and tint base.
4. Runtime clones preserve opaque/depth/cull state and tint only `mat/tint_base`.
5. Standard PBR lighting uses bright scene ambient `(0.85,0.88,0.95)`, exposure `1`, strong white emissive, and tint emissive `0.32×roleColor`.
6. At the current view and 18 px footprint, the charcoal region collapses to nearly no full-coverage pixels, leaving white and bright tint dominant over the live video.
7. Video is below the canvas; transparent camera-mode clear does not blend through fully opaque marker interiors.

## Most Likely Root Cause

Primary cause is a low-resolution silhouette/contrast failure at the current 18 CSS px footprint, amplified by bright ambient/emissive PBR output over live video.

Runtime probe at `844×390`, DPR 1:

- exact marker bbox: `18×18 CSS px`;
- 268 covered pixels;
- 226 pixels (`84.3%`) alpha 255;
- 42 antialiased partial-edge pixels;
- only `1/226` fully covered pixel was dark from the +Z view;
- bright full pixels: nose `160/226`, left wrist `87/226`, right wrist `142/226`.

DPR 2 produced `37×36` framebuffer pixels (approximately 18 CSS px), with `951/1033` alpha-255 pixels. More framebuffer pixels do not increase CSS-scale readability.

## Alternative Hypotheses

1. **Material alpha/transparency — contradicted.** GLB and live clones are alpha `1`, `BLEND_NONE`, depth-write/test enabled.
2. **Z-fighting/layer defect — contradicted.** Marker AABB Z is approximately `.3565...5435`; Grid/timing toggles changed `0/226` fully opaque interior pixels; layers do not clear depth.
3. **Missing normals/culling — contradicted.** Marker has explicit outward normals, 168 outward triangles, back-face culling, and no old `0.0.6` winding defect.
4. **DOM video/canvas opacity — contradicted.** Video is z-index 1, canvas z-index 2, with no canvas opacity; fully opaque marker pixels replace video.
5. **Pool/context corruption — contradicted.** Generation-owned instances are recreated and material roles survive import.
6. **Truthful near-object occlusion — possible situationally, but not the systemic live-video washout.

## Why Previous Fixes Failed

- Marker `0.0.7` repaired winding, opaque contract, role tinting, and CSS-size enforcement.
- Large review renders proved asset structure, but not structure at 18 CSS px over moving video.
- Existing browser gates assert presence, rough area, size ratios, material names, and depth behavior—not live-camera composite contrast.
- Correcting alpha or depth would treat a nonexistent transparency defect and break truthful rendering.

## Unknowns

- The smallest physically acceptable size among `18/24/28/32 CSS px`.
- Whether size increase alone is sufficient or an append-only marker asset successor needs a wider camera-independent charcoal silhouette band and white separator.
- Exact marker-specific emissive/lighting values that preserve contrast across all eight environments without changing global scene lighting.

5. Repeat with Grid/timing enabled and disabled; interior opacity is unchanged while silhouette readability remains poor.

## Proposed Verification

Run a physical and automated size sweep at `18/24/28/32 CSS px`, selecting the smallest passing value. Matrix:

- direct and genuine iframe;
- `390×844` and `844×390`;
- DPR 1 and requested 3/capped 2;
- nose/left/right at center, edges, and corners;
- all eight environments;
- moving camera imagery sampling white, black, skin, blue, green, and high-frequency clothing;
- raw framebuffer plus final DOM composite;
- Grid/timing/track on/off;
- truthful near/far occlusion, repeated-frame flicker, context restore, reconnect, and multi-instance isolation.

Assert exact CSS bbox, high full-alpha interior fraction, meaningful per-region dark/white/tint projected area, local perimeter contrast, immutable material state, and no public pixel/pose leakage.

## Recommended Fix

1. Do not change alpha, disable depth/culling, force always-on-top, or move landmarks.
2. Physically test `18/24/28/32 CSS px`; expected viable range is 28–32 px.
3. Prefer append-only asset-owned contrast if size alone is insufficient:
   - wider, camera-independent, non-coplanar charcoal silhouette band;
   - stable white separator;
   - meaningful projected area for each structural role at minimum size from cardinal views;
   - only tint core remains role-tintable;
   - alpha 1, opaque blend, back culling, outward normals, semantic bounds retained.
4. Tune marker-specific materials before touching global environment lighting.
5. Add genuine live-video composite gates and retain Derrick's physical retest as final authority.
