# 0.0.66 Visual Test equipment authoring diagnosis

## Exact Observed Failure

Derrick observed that Test equipment is visible while Test plays but disappears when the Test transport is paused. A pure reproduction of `gameplayEquipmentRecords()` returned:

```json
{
  "visualTestPlaying": 2,
  "visualTestPaused": 0,
  "playPaused": 0,
  "menuOpenVisualTestPaused": 0,
  "trackingPausedVisualTestPlaying": 0
}
```

The requested authoring controls do not yet exist: Visual Test always alternates synthetic GREAT/MISS feedback, and `TEST_EQUIPMENT_INPUT` always supplies fixed left/right wrists at `(0,0.5)` / `(1,0.5)`.

Direct observations:

- `pauseVisualTestTransport()` stops the loop, sets `paused_manual`, and explicitly calls `renderGameplay()`.
- The equipment preview toggle remains set; it is not reset by transport pause.
- `gameplayEquipmentRecords()` rejects every state except `countdown` and `playing`, so the explicit paused frame sends `equipment=[]` and the renderer correctly clears the models.
- Synthetic target hit/miss is privately derived in `projectSessionTargets()`.
- Persistent synthetic hit aftermath is independently derived from even `feedbackIndex` entries in `projectAftermathEntries()`; disabling only target labels would leave automatic hit debris.
- Visual Test equipment uses private deterministic `TEST_EQUIPMENT_INPUT`, not input/CV/gameplay truth.
- The renderer owns right-click pointer-lock, document mousemove, keyboard movement, and touch camera authoring while debug camera input is enabled.

## Expected Behavior

- `paused_manual` must retain equipment only for `session.purpose === "visual_test"`, subject to the existing preview, menu, tracking, calibration, countdown, confidence, and anchor gates.
- A checked-by-default private Test checkbox must enable current automatic GREAT/MISS behavior; unchecked must suppress both synthetic result feedback and synthetic hit aftermath without affecting real Play judgements/aftermath.
- A private Off/Left/Right selector must default Off. With preview on and a hand selected, finite canvas mouse coordinates drive only that synthetic wrist and render immediately while playing or paused. The other wrist remains deterministic.
- The last valid canvas position should remain latched while Derrick moves the cursor into the controls to tune values; mode Off, fresh Test, hidden/terminal lifecycle, disconnect, or teardown clears it.
- Selecting a hand must release and suspend free-fly authoring input without resetting the authored camera pose; returning Off restores existing free-fly behavior.
- No authoring state may enter snapshots, events, iframe messages, storage, gameplay/input/CV, scoring, persistence, or YAML.

## Execution Path

### Pause disappearance

1. Test transport Pause calls `pauseVisualTestTransport()`.
2. Audio/CV pause and gameplay transitions to `paused_manual`.
3. Assembly synchronizes the paused clock and calls `renderGameplay()`.
4. `renderGameplay()` retains `testEquipmentVisible` and uses Test synthetic input.
5. `gameplayEquipmentRecords()` rejects `paused_manual` before evaluating purpose or anchors.
6. Renderer receives an empty equipment list and removes both models.

### Automatic feedback

1. `rendererFrame()` projects the current content timeline.
2. `projectSessionTargets()` detects purpose `visual_test` and assigns even entries hit at center time, odd entries miss after the late window.
3. `projectAftermathEntries()` independently scans the full event index and materializes persistent aftermath for even entries.
4. Neither path currently accepts a Test authoring option.

### Mouse hand

1. `renderGameplay()` selects constant `TEST_EQUIPMENT_INPUT` for Test.
2. The same fixed anchors feed Flow zone direction and equipment record generation.
3. Canvas mouse coordinates are not currently collected by assembly.
4. Renderer free-fly listeners remain active and can enter pointer lock, where absolute mouse position is unavailable.

## Most Likely Root Cause

The pause regression is an over-broad legacy state gate retained when Test equipment was first admitted: purpose suppression was removed, but `paused_manual` remained globally excluded. The missing authoring behaviors are absent private control seams rather than gameplay defects. Automatic feedback has two independent derivations, and pointer ownership is split between assembly UI and renderer camera input; both must be coordinated explicitly.

## Alternative Hypotheses

1. **Stopping the frame loop clears equipment.** Rejected: pause explicitly renders after stopping.
2. **Pause resets the visibility toggle.** Rejected: reset occurs on fresh Test/lifecycle reset, not transport pause.
3. **Renderer cannot draw paused equipment.** Rejected: the renderer receives `[]`; suppression is upstream.
4. **Disabling target feedback alone disables all GREAT visuals.** Rejected: aftermath is regenerated independently from the render index.
5. **Shadow-root pointermove alone is sufficient.** Incomplete: renderer pointer lock and keyboard/touch camera inputs can still move/capture the camera; deterministic mutual exclusion is required.
6. **Backing-store/DPR coordinates should be used.** Rejected: equipment anchors are normalized CSS-space body-grid coordinates; using canvas pixels would double-scale on high DPR.

## Why Previous Fixes Failed

The 0.0.65 work solved initial Test equipment absence with deterministic renderer-only wrists and a visibility toggle. It preserved the pre-existing equipment state gate and did not exercise real transport pause. Existing browser coverage stops in playing Test. Automatic feedback and camera authoring predate this new tuning request, so no disable or mouse-hand contract existed.

## Unknowns

- Pixel-perfect mouse coincidence after a previously authored non-default free-fly camera pose is not guaranteed by normalized body-grid mapping. The approved 0.0.66 scope uses the existing production marker coordinate contract and suspends further camera movement while a hand is selected. A private renderer ray/unprojection API is a future option only if physical QA shows normal marker mapping is insufficient.
- Exact browser pointer event behavior under genuine cross-origin iframe remains to be verified by the focused browser oracle.

## Minimal Reproduction

Paused disappearance:

1. Start Visual Test.
2. Enable Test equipment preview.
3. Observe two equipment records while session state is `playing`.
4. Pause with the actual Test transport.
5. Observe state `paused_manual`, toggle still enabled, but equipment records become empty.

Pure equivalent: call `gameplayEquipmentRecords(false, {state:"paused_manual", purpose:"visual_test"}, healthySyntheticInput, "flow")`; current output is `[]`, while changing only state to `playing` emits two records.

Automatic feedback: project a two-note Test timeline after the first center and after the second late boundary; current output deterministically reports hit then miss, and the aftermath projector retains the even hit.

## Proposed Verification

1. Pure equipment oracle admits exactly paused Visual Test and rejects paused Play/menu/tracking/calibration/countdown/invalid-anchor controls.
2. Projection oracle with the new boolean off keeps Test targets pending until cull, never hit/miss; default on remains byte-compatible; Play real results remain unchanged.
3. Aftermath oracle with the boolean off emits no synthetic Test aftermath; default and Play controls remain unchanged.
4. Browser oracle uses real Test transport pause, confirms equipment persists, live config still rerenders, and resume remains visible.
5. Browser pointer evidence moves only the selected wrist, clamps coordinates, latches the last position while controls are edited, and resets on Off/fresh Test/lifecycle teardown.
6. Browser verifies selecting a hand releases/suspends free-fly capture/input and Off restores it without camera-pose reset.
7. Direct/cross-origin privacy assertions prove authoring state is absent from public surfaces.

## Recommended Fix

- Narrow equipment state admission to `countdown`, `playing`, or `paused_manual` only with `visual_test` purpose.
- Append a default-true synthetic-feedback parameter to both pure projection functions and pass one private assembly checkbox state to both.
- Replace constant Test input selection with a pure private Test input projection that overrides only the selected wrist from finite clamped canvas CSS coordinates.
- Latch the last valid pointer position for control-panel tuning; clear it at explicit lifecycle boundaries rather than pointerleave.
- Add a private renderer camera-authoring-input enable switch that releases current capture and ignores right-click/keyboard/DOM/touch camera input while false without resetting camera pose. Assembly sets false for Left/Right and true for Off.
- Add pure, direct-browser, and genuine cross-origin privacy/regression coverage before release.
