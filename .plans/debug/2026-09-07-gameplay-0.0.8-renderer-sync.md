# Gameplay 0.0.8 renderer sync diagnosis

**Date:** 2026-09-07  
**Bead:** `aerobeat-web-assembly-7znm`  
**Baseline:** renderer `b8a548189ed796dffb97719ec92876602d6d1f46`; asset release `8b190eecffdbdfc5dc914ea8e1d2f724bbcdc4d0`

## Exact Observed Failure

The first owned sync attempt failed before copying files:

```text
Error: source marker material/depth/culling contract mismatch
at scripts/sync-gameplay-assets.js:53
```

The sync tool expected detailed athlete-marker material/culling fields in `proof.v1.json`. Release 0.0.8 instead records the marker as byte-identical to 0.0.7 and keeps the detailed contract in the copied per-asset manifest.

## Expected Behavior

The renderer sync must fail closed on the exact 0.0.8 commit/full tree/raw tree/inventory/proof/set identities, verify the four unchanged GLBs against immutable 0.0.7, and validate material roles from each selected per-asset manifest before copying the exact 17-file release.

## Execution Path

1. `sync-gameplay-assets.js --sync` verifies Git provenance and release hashes.
2. It parses top-level inventory/proof.
3. The legacy marker assertion reads `proof.claims.athlete_marker.runtime_tint_material`.
4. The 0.0.8 proof intentionally exposes only byte-identity/dimensions for that unchanged role, so the old assertion fails.
5. No renderer asset tree is replaced because copying occurs later.

## Most Likely Root Cause

The sync oracle was coupled to 0.0.7's top-level proof shape. The append-only 0.0.8 proof changed its summary shape while retaining the exact detailed contract in `manifests/athlete-marker/sphere-v1.v1.json`. Runtime tint policy also needs the new changed-cue manifest `materialRole` metadata rather than name regex inference.

## Alternative Hypotheses

- Asset corruption: contradicted by exact commit/tree/raw tree/inventory/proof hashes.
- Dirty asset source: contradicted by clean `main == origin/main`.
- Copy permission failure: contradicted because execution stopped before copy.

## Why Previous Fixes Failed

No repair had been attempted. The 0.0.7 sync assumptions had not yet been generalized for an append-only successor with changed cue identities and explicit material roles.

## Unknowns

PlayCanvas may not retain glTF extras on cloned `StandardMaterial` objects. Verification must determine runtime availability; the safe design is to validate manifest metadata during sync and carry an immutable asset-id/material-name role table into renderer-owned code.

## Minimal Reproduction

At renderer baseline with only 0.0.8 authority constants updated, run `node scripts/sync-gameplay-assets.js --sync`; it deterministically fails at the marker proof assertion.

## Proposed Verification

Validate the marker from its selected manifest; validate arrow/circle/guard exact role/tint contracts from their selected manifests; compare unchanged GLBs with 0.0.7; run sync and verify modes; then run unit, Chromium, insecure, and pack inventory gates.

## Recommended Fix

Move detailed role assertions to selected per-asset manifests. Keep top-level proof checks for release-wide claims. Export a frozen role table derived from those audited identities and make runtime appearance apply only `note_fill` for dynamic/success tint, `marker_fill` for cursor role tint, and no fixed cue role.

## Rounded-edge pixel oracle follow-up

### Exact Observed Failure

After the material-role repair, the renderer Chromium test passed through actual GLB loading, environment, appearance, camera, and direction matrices, then `validate-grid-target-layering.js:61` failed its inherited near-white grid/arrow readback ceiling with `unchangedRatio=0.9939148073`, `meanShift=0.3042596349`, and `maxShift=14` (legacy maximum tolerance `12`).

### Expected Behavior

The target-layer exception must preserve prior opaque grid depth/color apart from bounded physical antialiasing at the newly rounded, substantially denser arrow silhouette. Central grid pixels must remain unchanged and the average shift must stay negligible.

### Execution Path and Root Cause

The oracle masks near-white pixels around an arrow and compares framebuffer values before/after target insertion. Asset 0.0.8 intentionally replaces the 136-triangle hard polygon with a 1,928-triangle rounded/beveled physical silhouette. Edge coverage therefore changes at pixels included in the broad near-white mask. The observed 99.39% unchanged ratio and 0.304 mean shift prove layer/depth behavior remains stable; only the single-pixel maximum rises from 12 to 14. This is an oracle calibration mismatch, not a renderer layering regression.

Alternative hypotheses—wrong layer, depth clear, transparent cue, or broad wash—are contradicted by target layer 6, opaque/depth-write truth, `unchangedRatio>0.993`, and low mean shift. No previous repair was attempted.

### Recommended Fix and Verification

Retain the existing `>0.99` unchanged-ratio bound and widen only the antialiased-edge aggregate from mean `<0.2`/maximum `12` to mean `<0.4`/maximum `16`, still far below a visible color wash. Rerun the complete grid/target pixel oracle and full browser suite; any broad layering regression will continue to fail the ratio/mean constraints.

## Terminal iframe module-load lifetime follow-up

### Exact Observed Failure

The unchanged full browser suite passed all contexts and every lifecycle/privacy oracle it includes. The additional terminal matrix passed isolated direct desktop, direct mobile, and genuine-iframe mobile shards, but the special genuine-iframe `1280×720@1` ownership shard failed three times before fixture installation with:

```text
locator.evaluate: Resulting promise was garbage collected.
at installFixture (validate-product-shell-matrix.js:222)
```

No terminal row or product assertion had begun. Direct `1280×720@1` passed all six terminal, 12 selection/action ownership, and 12 action/selection-purpose rows; genuine iframe `390×844@1` passed its six rows. The failure is isolated to the first dynamic production-audio module import inside the node-bound `locator.evaluate` callback for the desktop iframe.

### Expected Behavior and Execution Path

Terminal fixture setup must load the real web-audio constructor, synchronously replace the reconnect graph factory, remove/reappend the element, and then run the unchanged 36+24+24 matrix. The module import is not itself the lifecycle behavior under test.

### Root Cause and Alternatives

The Playwright node-bound evaluate promise loses its remote lifetime while Vite resolves/loads the first dynamic module in the large cross-origin iframe. This is an evaluation/module-load lifetime race, not a product lifecycle assertion: the same product graph and rows pass direct desktop and iframe mobile, and the normal complete genuine-iframe product/browser suite passes. A lifecycle regression, renderer fallback, or privacy failure is contradicted by those completed rows and full-suite evidence. Larger 0.0.8 preload work makes the first uncached iframe module load the distinguishing condition, but no renderer/page crash or console error is directly observed.

### Recommended Fix and Verification

Preload/cache the terminal-only audio module in a separate awaited child evaluation before binding the reconnect fixture callback, and make the element detach/reappend callback synchronous so its node-bound remote result cannot be collected mid-await. Keep every production-audio fixture, row, timeout, cross-origin, privacy, and assertion unchanged.

Verification PASS: isolated direct and genuine-iframe desktop ownership shards passed, all four mobile/orientation shards passed, and the exact aggregate gate passed `36` terminal + `24` selection/action ownership + `24` action/selection purpose rows.
