- For the **reproduced knee visibility gap with a visible knee but missing ankle**, `body-grid-service.js:1251–1255` only publishes a leg if *all three* hip/knee/ankle confidence values exceed .5; assembly `rendererFrame` consequently receives no joints and native pad/marker disappear even though the Worker sees the knee. The new signed Play run observed confident hip+knee 145/145 times, no confident ankle 109/145 times, and no pad 108/109 such frames. Derrick specifically says the knee enters view after T-pose and does not require an ankle to draw the equipment. This is an identified product eligibility mismatch, not proof his exact camera's ankle confidence. Preserve the ankle requirement **for scoring** while giving only the visual projection a separate measured hip/knee path. Do **not** widen the 150-ms cutoff based on unrelated phone metrics.
- Independently, the isolated signed Worker wrist error is a timing mismatch: a newly arriving measured Worker frame can already be older than the scorer's 150-ms current-frame limit. A non-frozen 166-ms measurement fails current-wrist validation despite high wrists. This can interrupt frames but is not established as the cause of Derrick's original absence; do not use it to justify changing scoring freshness.
- For the reproduced **`Invalid public array`**, the root cause is **proven for the signed paused Boxer→Flow path**: the content telemetry snapshot copies an unbounded real `playback.judgedEventIds` array; the future-only paused mode swap retains that run's 101 judgements and explicitly emits a `content_changed` event capped at 96. Another personal package or route could expose an additional array problem, but no such separate defect is demonstrated.
