# Diagnosis: Test→Play broken state (raw 0.0.49) — bead `aerobeat-web-assembly-k85i`

_Date: 2026-09-10 · Source: read-only diagnosis subagent (report verbatim)_

## Root cause — exact transition defect + state sequence

**Defect in one line:** an accepted mid-session Play intent clears its own Test-truth assembly flags *synchronously, before* the serialized FIFO turn runs its teardown; when that FIFO turn then bails at the first post-`await` ownership check, **nothing ever stops the old transport and nothing restarts anything**. The session is left with `sessionStartRequested=false`, `activeSessionAction=""`, `pendingSessionAction=""`, menu closed, while audio is still playing, the gameplay coordinator is still `playing/visual_test` with a stale visual-test lease snapshot, no camera/CV, and no calibration.

Assembly file: `aerobeat-web-assembly/src/index.js`

1. **Routing.** `aero-session-actions` emits `session-start` → `handleUiIntent()` routes to `startFromMenu("play")` (`index.js:2012`, `startFromMenu` at `1945`). There is **no special case** for "an action is already active": every accepted Start/Test goes through `startSession(purpose)` (`index.js:301`) — i.e., the same FIFO controlled fresh-restart path (`enqueueLifecycleIntent`, `index.js:282`). So the UI layer (buttons always enabled, `aero-product-presenters.js:514-525`; `sessionActionsSnapshot()` at `index.js:1984`) is not where it breaks.

2. **The premature commit.** `startSession` sets pending/active truth synchronously on entry (`index.js:305`), but the body of the queued FIFO turn immediately resets it: `this.sessionStartRequested = false; this.activeSessionAction = "";` (`index.js:309`, executed after the prior lifecycle-intent tail settles). That flag clear is what makes the test UI hide: `visualTestTransportSnapshot().active = sessionStartRequested && activeSessionAction==="test" && purpose==="visual_test"` (`index.js:1246`), transport element hides on `!snapshot.active` (`aero-visual-test-transport.js:212`). This is exactly the half the user sees: UI hidden, song still going.

3. **The bail-out.** In the common physical layout (menu open during a running Visual Test): opening the menu pauses the run (`setMenuOpen(true)`, `index.js:1895-1915`; `configureContent` preserves `paused_manual` for visual_test, `aerobeat-web-gameplay/src/session-coordinator.js:163,188-191`). Pressing Play enqueues the turn; the turn awaits `previousMenuPauseTail` (`index.js:317`). If the user closes the menu during the pause (the natural way to get back to the play surface), close-with-disposition `active-paused` arms the auto-resume of the *existing Test transport*: `void this.resumeVisualTestFromMenu(graph)` (`index.js:1923`), which calls gameplay `resume()` and returns `accepted:true, purpose:"visual_test", state:"playing"` (`session-coordinator.js:280-284`). That resume increments **gameplay** generation only — assembly `sessionGeneration` is unchanged. When the paused tail settles and control re-enters the turn at `index.js:318`, `isActionIntentOwner(owner, sessionGeneration, actionGeneration)` (`index.js:298` → `297` → `288`) compares the turn's allocated generation against the current `lifecycleIntentActiveGeneration`. Any other accepted lifecycle intent that ran meanwhile (e.g. the menu-close chain or any content/profile setup-sensitive operation) advances `lifecycleIntentGeneration`, so the comparison fails and the turn does `return this.getSnapshot();` — `index.js:318` (likewise `315/320/325/335/342/347/353/357`). Because line 309 already cleared the flags, the failure branch does not restore them (the `finally` only restores them if the whole session never committed, `index.js:371`); the teardown lines `stopFrameLoop / audio.stop / cv.stop / video.pause / seek(0)` (`index.js:323-327`), the configure (`329`), the resource acquisition (`331-336`), the Play block (`337-348`: camera request, `video.play`, `startCv`), and `requestStart(PLAY_START_REQUEST)` (`index.js:356`) are all skipped. The rollback `finally` is inert: no media was acquired yet by this turn (`mediaLeaseGeneration===null`, `cameraAcquisitionAttempted===false`, …, `index.js:367`).

4. **Stale-state confirmation at the coordinator.** `graph.gameplay.setLeaseSnapshot(...)` is only called *inside* the FIFO body (`index.js:336,354`); nothing else refreshes it per-frame. After the old Test turn bailed out, the coordinator keeps the last published lease snapshot (audio-only, owner=this instance), so `hasRequiredLease()` (`session-coordinator.js:571-574`) stays true even though the real lease belongs to the still-running Test transport. `advance()` therefore keeps committing `timelinePositionMs` for `playing/visual_test` (`session-coordinator.js:318-334`) — the "song does not restart" half. For `purpose==="play"` there is zero input commitment (`commitInput` only under play, `session-coordinator.js:314`) and zero safety enforcement (`enforceSafety` early-returns for visual_test, `session-coordinator.js:549`), so no T-pose/calibration appears either: neither "mode swaps over and calibration starts" nor any visible recovery occurs. Assembly side, `startCv` is also gated off because the live purpose is still `visual_test` (`index.js:1092`), so even a later implicit trigger could not start CV.

### State sequence (Test active+playing, menu closed, Play pressed)

| holder | value |
|---|---|
| assembly (pre-press) | `sessionStartRequested=true`, `activeSessionAction="test"`, `pendingSessionAction=""`, `lifecycleIntentActiveGeneration=0`, `lifecycleIntentGeneration=N`, `sessionGeneration=G`; lease held (audio) by the Test participant; frame loop running; transport UI active |
| game coord (pre-press) | `state="playing"`, `purpose="visual_test"`, timeline advancing with the audio clock; lease snapshot = audio-owned |
| press → sync (index.js:305) | `pendingSessionAction="start"`, `pendingSessionActionOrdinal=N+1`, `menuStarting=true`; `sessionActionIntentOrdinal++`; `actionGeneration=sessionActionGeneration` |
| FIFO turn begins (index.js:307-309) | allocates `sessionGeneration=G+1`; clears preview/menu/transport tails; **clears `sessionStartRequested=false`, `activeSessionAction=""`** → renderPresenters() → **transport hides** (the symptom Derrick saw) |
| turn bails (index.js:318) | `isActionIntentOwner` false (lifecycle tail moved past this token) → return; teardown/reconfig/lease/requestStart skipped; rollback inert |
| final | assembly: no active/pending action, menu closed; game coord: `playing/visual_test` still advancing (stale audio-only lease); audio playing; no camera, no CV, no `calibrating`; Play button re-enabled (pending cleared in finally, index.js:372) → looks idle while music plays |

With menu closed and no interleaved intent, the same path proceeds fully and works (that is why the existing supersession row passes) — the break requires the menu-open/auto-resume interleaving (or any second accepted setup-sensitive intent between allocation and the check), which is exactly what physical use produces.

## Proposed fix (minimal, concrete — no code changes made)

Goal: the in-session switch must be indistinguishable from a cold Play, and it must be **queued, not dropped/no-opped**.

1. **Do not destroy the outgoing mode's truth inside the FIFO turn.** Remove/clean up the synchronous reset of `sessionStartRequested` and `activeSessionAction` at `index.js:309` so those two flags flip only at the commit point (`index.js:355`) where they are set to the new action. Keep everything else on line 309 (preview stop, menu/transport/audioSync tail resets, `menuDisposition`, `terminalReconciledSessionGeneration`). Effect: the old Test transport stays visible until the fresh Play has actually committed; the "UI hides" step moves atomically with the mode swap. (Display-semantics change flagged for Derrick — see parent disposition.)
2. **Make ownership failures explicit instead of silent no-ops.** Every `if (!this.isActionIntentOwner(...)) return this.getSnapshot();` bail inside `startSession` (`index.js:312-357`) currently abandons a *freshly accepted* ordinal. On bail of the newest action (`actionIntentOrdinal === this.sessionActionIntentOrdinal`), the turn should fall through to the rollback `finally` (treat as uncommitted: quiesce frame loop, stop any audio/CV/video started or still running under the incoming lease identity, release this action's generation if acquired, restore `pendingSessionAction=""/menuStarting=false/renderPresenters`), so the invariant "every accepted action ends in exactly one committed fresh session" holds and the next click starts cleanly. Optionally surface a bounded error ("restart did not apply — try again") instead of silently returning.
3. **Guard the Test-transport auto-resume so it cannot steal the window.** At `index.js:1923` (`resumeVisualTestFromMenu` from close-of-active-paused), skip auto-resume when `this.pendingSessionAction !== ""` or `this.menuStarting` (a new action is queued and owns the next generation). Symmetric guard at the transport-play entry: `enqueueVisualTestPlay()` (`index.js:467`) and `resumeVisualTestTransport()` (`index.js:503`) should no-op (or defer) while `sessionActionIntentOrdinal` has advanced past the session that armed the transport — this also prevents a stale Test Play from racing a fresh cold Play. These three changes together make the switch strictly: queue behind prior work → full teardown (`index.js:323-327`) → zero seek → configure (`329`) → purpose resources (`331-336`) → `requestStart` (`356`) → awaited initial-audio commit (`358`) — identical to cold Play, and symmetric for Play→Test (same function, `resources=["audio"]` branch at `331`, no camera/CV branch at `349-352`).
4. **No coordinator-side change required.** The gameplay session coordinator behaves correctly given correct call order (its `requestStart` explicit branch already performs the full fresh-reset semantics, `session-coordinator.js:212-253`, and `configureContent`'s non-visual_test branch enters `calibrating` at `196-199`). The defect is entirely in the assembly FIFO ownership/flag-lifecycle.

## Oracle plan

Add to `scripts/validate-product-shell-matrix.js` (owns the 36-row terminal oracle + the 24-row selection-action-ownership and 24-row action-selection-purpose matrices; wired via `npm run test:terminal-lifecycle-matrix`), as a new cross-product shard modeled on `verifySelectionActionOwnershipRows` (`:301`): **in-session mode-switch rows**, e.g. `2 embeddings × 2 modes (Test-active→Play, Play-active→Test) × {menu-closed direct, menu-open+close interleaving} = 8 rows minimum`, asserting per row:

Sequence A — Test(active)→Play:
- Setup: real fixture package, `startSession("visual_test")` settled to `playing/visual_test`; subscribe gameplay publications and install restart trace (mobile-harness seam pattern, `validate-mobile-gameplay-menu.js:49-54`): audio source ordinal, audio state/clock, `cvStartCalls`, camera requests, lease generation/resources, `gameplay.requestStart` entries.
- Step 1 (interleaving variant): `setMenuOpen(true)`, await `menuPauseTail`, assert `paused_manual/visual_test`; click Play; assert in-flight `pendingSessionAction="start"`, `menuStarting=true`; close menu; await `menuPauseTail` + `lifecycleIntentTail`.
- Expected: `gameplay.generation` strictly increases; exactly one new `gameplay-request-start` with `purpose:"play"`; final session `state="calibrating"`, `purpose="play"`, `pauseReason="calibration_required"`; audio stopped then played once and frozen at 0 ms aligned with `timelinePositionMs===0`; lease resources `["camera","audio"]` on the new generation; camera requests +1, CV starts +1; test transport `active:false/hidden`; transient cue "T-pose" visible; old-generation lease snapshot replaced; no `play/*` or `visual_test/*` publication may appear without owning the new generation. Hard global invariants: `activeSessionAction==="test" ⇒ session.purpose==="visual_test"` and `activeSessionAction==="" ⇒ no active transport with session.state!=="completed"`.

Sequence B — Play(active)→Test:
- Setup: `startSession("play")` with fixture camera/CV to `calibrating/play`; click Test.
- Expected: single `requestStart` `purpose:"visual_test"`; final `state="playing"`, `purpose="visual_test"`, `timelinePositionMs===0`, audio playing at 0, lease `["audio"]` only, camera request delta 0 (retained stream untouched per `index.js:338-345`), CV running false, calibration badge inactive, test transport `active:true`, no T-pose cue, `generation` increased exactly by the restart.

Also: double-press-during-inflight (second Play while first Play queued) expecting strict FIFO (two restarts, one committed per turn, final Play), and a destroyed/disconnect row confirming queued switches invalidate cleanly. Extend the exact-count asserts at `validate-product-shell-matrix.js:56` accordingly. Unit-level mirror in the assembly unit suite around `startSession`: allocate → interleave a second intent → force the first to fail ownership → assert no media remains owned by the failed turn and UI returns to actionable idle.

## Risks / unknowns

- **Fix #1 changes visible behavior**: the outgoing-mode transport stays visible until the new action commits (a short beat during teardown/seek). If Derrick expects "hide immediately then restart", keep the immediate hide but make the bail path restore truth explicitly — that variant is uglier (two UI states mid-restart) and needs his call. **Parent decision recorded:** the atomic-swap behavior (option 1) is the default; Derrick may override.
- **Interleaving coverage gap confirmed:** none of the existing oracles crosses an in-session action switch. The 24-row supersession row queues both actions from a *closed* menu with no auto-resume interleaving, so the broken window is structurally absent; the 36-row terminal matrix covers only completed-run edges; the 24-row action-selection rows cover Gameplay selections after Test, not Play/Test switches.
- **Uncertainty #1:** not executed; whether *any* second intent lands between allocation (line 307) and the check (line 318) depends on the physical micro-sequence. The static evidence shows the bail exists, is reachable, and leaves exactly the reported split state; a deterministic delayed-gate repro will pin the exact interleaving in the red-path run.
- **Uncertainty #2:** `isActionIntentOwner` uses `>=` plus active-token equality; the precise scheduling edge where it flips for the menu-close chain is timing-dependent, so the fix must not rely on making the owner-check pass more often — it must make failing acceptable outcomes impossible.
- **Scope note:** Play→Test shares the identical code path (`startSession`), so the same defect class applies symmetrically; oracle rows B cover it.
- **Adjacent (out of scope for k85i):** Game-setup drawer copy says timing/collider changes apply "on next Start/Test" — after the fix, in-session switches genuinely re-apply setup via `configureGameplayFromContent(..., bindDesiredSetup=true)` (`index.js:329`), so that copy becomes accurate for in-session switches too. (Note: guidance-band live switching per `er3m` is a separate renderer-input change.)
