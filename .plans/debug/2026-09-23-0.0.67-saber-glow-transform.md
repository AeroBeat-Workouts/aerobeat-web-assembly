# 0.0.67 saber glow transform diagnosis

## Exact Observed Failure

Derrick's screenshot (SHA-256 `fe8218ad4dac6d8df54e8cf42ec80887d2c4fe736bb67170f816070fde7619e4`) shows the green saber glow attached beside rather than aligned over the blade.

Direct inspection found:

- The runtime GLB, glow, and primitive fallback use incompatible native-axis assumptions.
- Glow midpoint does not inherit saber scale.
- GLB and glow are unrelated root-level entities with independently reconstructed world transforms.
- Primitive fallback has no separate glow path.

## Expected Behavior

For each hand, model/core/glow inherit one wrist-anchored transform. Their axes remain collinear under direction, scale, moved camera, and arbitrary combined XYZ orientation. Scaling moves local centers and endpoints together. GLB and fallback share the same canonical geometry contract.

## Execution Path

1. Assembly emits direction, scale, and authored orientation.
2. Renderer validates and dispatches to `stageSaber()`.
3. GLB path places/scales/rotates a root entity and separately stages a root-level glow.
4. Glow reconstructs world midpoint, scale, and 2D rotation.
5. Fallback independently stages hilt/blade cylinders through `applyEquipmentTransform()` and omits the distinct glow.

## Most Likely Root Cause

Three confirmed defects cooperate:

1. **Shipped GLB axis mismatch.** Comments claim local `+Y`, but GLB hash `ed4fce456f4b665f5d3589861a2233b6c67becd86a0fcf5765bb5f48289f40d3` has no corrective node transform and vertex bounds along local `-Z`: hilt `0…-0.18`, blade `-0.18…-0.726`, tip `-0.726…-0.75`.
2. **Primitive axis mismatch.** PlayCanvas 2.21.4 cylinders use local `Y` as height, but current code scales them as if local `X` were the axis. Correct dimension order is `[2r,length,2r]`, not `[length,2r,2r]`.
3. **Unscaled midpoint.** Glow dimensions multiply by saber scale, while its center remains `0.48` world units from the wrist. At scale 2 the center should be `0.96`; drift is guaranteed.

Because model and glow are app-root siblings, independent reconstruction cannot guarantee equality under XYZ composition even if these constants are patched.

## Alternative Hypotheses

- Blend/depth behavior changes halo appearance but cannot produce the confirmed axis/midpoint divergence.
- Left/right mirroring is unlikely; each role has distinct pools but identical geometry math.
- Midpoint-only correction would improve scale 2 but leave GLB and primitive axes wrong.

## Why Previous Fixes Failed

- Glow gain and start tuning changed brightness/coverage, not geometry.
- Scale support resized model and glow but omitted scaled center offset.
- Blender checks inspected pre-export `+Y` source rather than shipped runtime `-Z` bytes.
- Unit stubs codified the wrong X-axis cylinder assumption.
- Existing composite pixel oracles isolate neither blade nor glow, use implicit scale 1, and can pass when only glow pixels satisfy aggregate bounds.

## Unknowns Resolved

- Preserve the current small glow tip halo (`0.03` local units) unless framebuffer evidence shows detached overshoot; it remains a child-local constant.
- Combined XYZ collision semantics are resolved in the companion equipment-pose report: transformed visual geometry becomes production hit geometry rather than a visual-only tilt.

## Minimal Reproduction

- Stage one GLB saber at a fixed wrist and `+X` direction; capture blade-only and glow-only masks at scales 1 and 2. Scale 2 exposes the midpoint drift.
- At scale 1, compare mask PCA axes: runtime GLB `-Z` and gameplay-plane glow diverge.
- Force fallback and inspect cylinder dimensions: native-Y primitives receive X-axis scale ordering and no distinct glow.

## Proposed Verification

Capture baseline, GLB blade-only, glow-only, composite, forced-fallback core-only, and forced-fallback glow-only masks for scales 1/2, both hands, cardinal/diagonal directions, combined XYZ, and canonical/moved cameras.

Require:

- model/core and glow descend from one per-role root and share its world matrix;
- true pixel centroids match projected local midpoints within 1 px;
- PCA axis difference from projected canonical `+Y` and between component masks is at most 1°;
- endpoints/extents match projected local bounds within 2 px;
- at least 98% of blade/core pixels lie inside a one-pixel-dilated glow mask;
- GLB/fallback midpoint/axis/endpoints agree within 2 px/1°;
- role disable removes the complete root and color changes do not alter geometry.

## Recommended Fix

Create one unscaled transform root per role at the wrist. Apply only uniform saber scale and one final quaternion to the root. Attach:

- runtime GLB with one fixed child correction from source `-Z` to canonical local `+Y` (or re-export with a truthful axis if provenance permits);
- fallback native-Y hilt at local `y=.09`, dimensions `[.06,.18,.06]`;
- fallback native-Y blade at local `y=.465`, dimensions `[.048,.57,.048]`;
- one shared native-Y glow at local `y=.48`, dimensions `[.09,.60,.09]`.

Child positions and dimensions remain unscaled. Root inheritance scales midpoint, extents, model, and glow together. Compose the documented world quaternion from gameplay heading, base local XYZ, and animated local XYZ, then use that identical pose for projected collision geometry.
