# 0.0.64 equipment panel/live preview and Boxing uppercut crash

## Exact Observed Failure

Derrick's physical raw 0.0.63 playtest reports:

- Equipment config is an editable YAML textarea rather than grouped field controls.
- The authoring panel is too narrow; Apply/Reset/Export button labels are oversized, wrap, and clip (screenshot SHA-256 `e6700f2813803edb7155f4902f35488358afb8a27d35d01b0b4f4ce491471670`, 497×831).
- Hand equipment is not visible in Test.
- Info box shows: `Cannot read properties of undefined (reading 'rotationZDeg')`.
- Boxing halts for several frames every few beats on Wario Ware Hard.

A minimal source-level reproduction on current `main` produces the exact Info error:

```text
selectGloveState(... family:'uppercut') => 'upercut'
Object.keys(validatedConfig.boxing.glove.states)
=> ['straight','uppercut','hookL','hookR','guard']
config.states['upercut'].rotationZDeg
=> Cannot read properties of undefined (reading 'rotationZDeg')
```

## Expected Behavior

- The panel exposes grouped native controls and applies every accepted field change to the next rendered equipment frame.
- Export remains deterministic YAML, but YAML is not the editing surface.
- Layout and buttons remain legible and unclipped at mobile/direct/iframe sizes.
- Test owns an equipment visibility toggle defaulting off; on must stage visible deterministic preview hands without requiring a camera/calibration flow.
- Every Boxing family, including uppercut, resolves a defined configured rotation without throwing or stalling frames.

## Execution Path

### Uppercut crash / periodic halt

1. `runDisplayFrame()` calls `renderGameplay()` each displayed frame.
2. Boxing calls `computeBoxingStateRotations()`.
3. `boxingUpcomingActions()` selects an upcoming uppercut for the relevant hand throughout the configured 500 ms lookahead window.
4. `selectGloveState()` returns the misspelled key `"upercut"`.
5. Validated defaults and serialized YAML contain the canonical key `"uppercut"`.
6. `computeBoxingStateRotations()` reads `config.states[state].rotationZDeg`; `config.states.upercut` is undefined and the read throws.
7. The outer frame-loop catch routes the repeated error to the Info surface. Every display frame while the uppercut remains selected can abort the remainder of display work, presenting as a multi-frame halt around periodic uppercut beats.

### Missing Test equipment

1. Visual Test deliberately runs audio-only and omits camera/CV/calibration/input from gameplay advance.
2. `renderGameplay()` still calls `gameplayEquipmentRecords()` with the input service snapshot.
3. That producer requires countdown/playing plus healthy calibrated tracking and valid wrist anchors.
4. Test has no such measured wrist evidence, so it emits no records.
5. The 0.0.63 browser Apply oracle had to monkeypatch `input.getSnapshot()` with synthetic wrists before it could inspect a next-render record, directly demonstrating this missing production preview path.

### Panel UX/layout

1. The template renders one full YAML textarea and three full-width buttons inside `.equipment-authoring`.
2. The panel inherits the narrow Visual Test authoring rail.
3. Button text is multi-word/filename text with inherited control font sizing and minimum 44 px height, so three controls in the narrow rail wrap/clip as shown.
4. Apply is a second-stage commit; textarea input only validates, so values are not live while Derrick tunes them.

## Most Likely Root Cause

Two independent design defects and one exact typo:

1. **Crash/performance:** canonical `uppercut` was misspelled as `upercut` in the state selector and exported state-key constant/tests, while the defaults/schema shape use `uppercut`. This exact mismatch reproduces Derrick's exact error and makes it beat-family periodic.
2. **Missing Test equipment:** C5 reused the production calibrated-input record gate instead of defining a private deterministic Test preview record source controlled by a visibility toggle.
3. **Panel:** C5 implemented YAML as the authoring state rather than treating validated config as state and YAML as export serialization only; the narrow inherited rail was not tested against real labels at Derrick's viewport.

## Alternative Hypotheses

1. **Renderer entity/asset churn causes Boxing halts:** still worth profiling after the uppercut fix, but the exact repeated exception aborting frames for a 500 ms beat window is a much stronger causal match.
2. **GC from target allocations:** possible secondary contributor; not needed to explain the exact Info error.
3. **A malformed exported YAML omitted uppercut:** contradicted by the baked defaults and validator producing `uppercut`; the selector itself returns the wrong key.
4. **Renderer rejects Test records:** contradicted by the prior browser oracle successfully rendering after synthetic input injection.

## Why Previous Fixes Failed

- 0.0.63 unit tests asserted the misspelled `upercut` value and `GLOVE_STATE_KEYS`, locking the defect instead of comparing against the actual validated defaults shape.
- Browser tests proved Apply changed an accessor and, later, a next rendered record only after monkeypatching synthetic input. They did not assert production Test visibility or exercise an upcoming uppercut through `renderGameplay()`.
- Layout inventory tests counted controls but did not assert button single-line fit or panel width at the screenshot viewport.

## Unknowns

- Whether any additional Boxing stall remains after eliminating repeated uppercut exceptions. Resolve with exact-chart target-hardware profiling.
- The final preview wrist positions/orientations to use when Test visibility is on. A neutral left/right pair centered within the grid is the minimal deterministic policy unless Derrick supplies another pose.
- Exact minimum panel width across supported viewports; resolve with direct/iframe mobile matrix and label overflow assertions.

1. Add a fail-before integrated Boxing render oracle that supplies an upcoming uppercut and asserts no exception plus the configured `uppercut.rotationZDeg` reaches the record.
2. Assert every selector result belongs to `Object.keys(validateEquipmentConfig(equipmentConfigDefaults).boxing.glove.states)`; do not duplicate a manually typed expected list.

5. Re-profile Wario Ware Hard or an exact uppercut-dense chart after the typo fix; require no periodic long-frame cluster.

## Recommended Fix

- Canonicalize the state spelling to `uppercut` everywhere: selector, constants, JSDoc, tests, and any serialized config assumptions.
- Replace textarea/draft/Apply state with grouped validated controls backed directly by `this.equipmentConfig`; every change clones one leaf, validates the complete candidate atomically, commits it, and renders next-frame live.
- Export `serializeEquipmentConfigYaml(this.equipmentConfig)` directly; Reset restores defaults and resynchronizes fields.
- Add private per-instance `testEquipmentVisible=false`. When true in Visual Test, stage two deterministic preview equipment records through the same renderer transform contract without entering scoring/input/calibration/public snapshots.
- Widen the Test authoring rail responsively and use compact single-line Reset/Export controls.
