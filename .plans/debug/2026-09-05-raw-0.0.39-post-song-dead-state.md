# Raw 0.0.39 post-song testing dead-state diagnosis

**Date:** 2026-09-05  
**Bead:** `aerobeat-web-assembly-4in`  
**Research:** `13a7631f-a300-4449-adf1-66b52f22945c`  
**Candidate:** immutable raw `0.0.39`  
**Disposition:** Root cause reproduced; Phase 4 repair implemented and CODER PASS recorded in the active plan (`4in` remains open for QA/audit).

## Exact Observed Failure

After a song ends, Derrick cannot reliably open the menu, select another gameplay mode/settings, close it, seek, and continue testing. A page reload is required.

Deterministic source-level reproduction:

`completed@duration → menu pause → paused_manual@duration → menu close resume → playing@duration → production audio play rewinds ended source to zero → gameplay detects clock rollback → paused_manual(audio_clock_rollback)`.

The old terminal timeline remains attached, producing the dead-end.

## Expected Behavior

Completion is a between-run state, not an active session that can be converted into a normal pause/resume:

- Menu may open and change mode/song/difficulty/settings without implicitly resuming the ended run.
- Closing from terminal state does not autoplay.
- Backward seek establishes an exact paused timeline; Play advances.
- Explicit Start/Test creates a fresh generation at zero with stale audio/CV/judgement state excluded.
- Play reacquires camera and calibration/countdown; Test remains audio-only.

## Execution Path

1. Audio `onended` fixes the clock at duration, pauses it, and sets audio state `stopped`; the service exposes no ended subscription.
2. Assembly continues polling the clock in its display loop.
3. Visual Test changes to `completed` when `!clock.playing && clock.ended`; scored Play completes when all outcomes resolve.
4. Assembly performs no terminal-edge reconciliation; display/CV/lease may remain active.
5. Opening the menu unconditionally calls gameplay `pause()`, converting `completed` to `paused_manual`, and sets `menuPauseArmed` unconditionally.
6. Mode selection now sees a paused active run and uses future-swap behavior without resetting generation.
7. Closing the menu unconditionally resumes a Visual Test paused session.
8. Production audio `play()` sees position at duration and rewinds to zero.
9. Gameplay sees the backward clock jump and correctly enters `paused_manual` with `audio_clock_rollback`.
10. Transport's serialized queue does not serialize the separate menu-close audio synchronization path.

## Most Likely Root Cause

Assembly destroys terminal semantics by treating `completed` as ordinary manual pause/resume. It then auto-resumes an ended one-shot audio source whose production contract rewinds to zero. Gameplay correctly rejects the rollback, leaving the old terminal generation stuck.

## Alternative Hypotheses

1. **Pointer/control reconstruction — lower likelihood.** Existing held-pointer tests cover much of this; reproduction requires no DOM replacement.
2. **Media lease/CV failure — adjacent.** Completion fails to quiesce/release them, wasting resources and possibly worsening performance, but rollback explains the deterministic dead-end.
3. **Content selection handling — contributor.** `completed/stopped` are omitted from between-run selection lists; menu pause masks this by changing state first.
4. **Mobile hit target — unlikely.** State edge is viewport/input independent.

## Why Previous Fixes Failed

Existing tests falsely certify terminal behavior:

- Fake audio `play()` does not reproduce production's rewind-at-duration behavior.
- Fake finish uses `paused`, not production `stopped`.
- `verifyPostSessionMenuStability()` returns the initial session state under `sessionState`, overwriting final truth; assertions inspect the initial `completed` value rather than the actual final coordinator state.
- Replay tests explicitly seek backward before replay and therefore never exercise menu-close auto-resume at terminal end.

## Unknowns

- Whether Derrick's exact sequence began in Test, scored Play, or both; the root transition can affect either.
- Desired UX for pressing transport Play while still exactly at completed end. Recommended: explicit fresh restart at zero, not resume.

## Minimal Reproduction

1. Configure Visual Test with an audio lease.
2. Start and advance until stopped clock at duration produces `completed`.
3. Open menu: unconditional pause yields `paused_manual@duration`.
4. Close menu: resume yields `playing@duration`.
5. Production audio play rewinds to zero.
6. Advance: gameplay detects rollback and enters `paused_manual/audio_clock_rollback`.

## Proposed Verification

Add a production-faithful audio integration fake where natural `onended` sets `stopped` and `play()` at duration rewinds to zero. Assert every intermediate session/audio/lease/CV/generation state. Repair the helper to assert `finalSessionState`.

Matrix: Flow, Boxing Lanes, and Boxing Grid × Aero and Camera backgrounds; Visual Test and scored Play; desktop mouse/keyboard and mobile portrait/landscape pointer/touch.

## Recommended Fix

1. Add explicit menu disposition: `active-paused` versus `terminal`. Opening from terminal does not call gameplay pause; closing terminal does not auto-resume audio/gameplay/CV. Make `menuPauseArmed` a truthful read gate.
2. Treat `completed/stopped` as between-run for variant, scoring profile, and mode selection.
3. Backward seek from completed explicitly normalizes to exact paused timeline. Play at exact end performs a fresh zero-generation request if approved.
4. Explicit Start/Test awaits stale transport work, stops/quiesces old media/CV, seeks zero, configures selected content, increments generations, clears old outcomes, and reacquires the purpose-specific lease.
5. Reconcile terminal services deterministically: stop display/CV work as appropriate, settle audio, and define lease retention/reacquisition.
6. Replace false-positive tests with production-faithful ended/rewind behavior and final-state assertions.
