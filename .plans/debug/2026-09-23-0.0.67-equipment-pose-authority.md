# 0.0.67 equipment pose authority diagnosis

## Exact Observed Failure

Equipment authoring exposes only scalar Z rotation and cannot tune independent or combined X/Y/Z axes. Flow and Boxing visual transforms also do not share authority with production collision geometry:

- Flow collision uses motion-derived saber direction and fixed geometry.
- Assembly independently substitutes eased zone direction for rendering.
- Renderer applies another visual-only base Z rotation.
- Scale affects rendering only: Flow scale 2 displays 1.5 WU while hit length stays 0.75; Boxing scale .75 shrinks the model while contact stays fixed.
- Flow zone y coordinates and clocks are mismatched.
- Flow and Boxing easing repeatedly apply elapsed progress to the remaining delta, making results frame-cadence dependent; Boxing can take the long path across ±180°.

## Expected Behavior

Independent X/Y/Z controls produce directly tunable combined poses. Base orientation, animated zone/state orientation, model, glow/fallback, and declared collision geometry derive from one documented pose. Transitions are shortest-path and frame-cadence independent. Config reset/export/import/bake are canonical and private.

## Execution Path

Current authoring path:

```text
defaults → validator → live controls → zone/state tracker
  → gameplayEquipmentRecords → renderer validation → GLB/fallback
```

Current Flow hit path is separate:

```text
wrist history → motion saber direction → fixed capsule → contact
```

Boxing likewise uses fixed glove dimensions independent of rendered scale/orientation.

## Most Likely Root Cause

The scalar `rotationZDeg` schema conflates:

1. per-hand model base orientation;
2. Flow gameplay heading;
3. Flow zone-local model pose;
4. Boxing state animation target.

Renderer became the only transform-aware layer while gameplay retained fixed geometry and motion-only orientation. No canonical pose resolver or composition contract exists.

## Alternative Hypotheses

- Treating this as UI-only is rejected: collision/render divergence and cadence-dependent trackers are production defects.
- A bad asset pivot explains part of the saber screenshot but not scale/collision divergence.
- Material effects may exaggerate glow but cannot explain the separate authorities.

## Why Previous Fixes Failed

Earlier work added scalar base/state rotations, glow start/gain, and zone-derived visual headings without one pose authority. Those changes adjusted presentation while production collision continued using independent motion/fixed geometry. Scalar interpolation also lacked fixed transition endpoints.

Use canonical `aerobeat/equipment_config` version 2:

```yaml

  perHand:
    left:  { scale: 2, rotationEulerDeg: { x: 0, y: 0, z: 0 } }
    right: { scale: 2, rotationEulerDeg: { x: 0, y: 0, z: 0 } }
  saber:
    zones:
      edgeTop:    { headingDeg: 90,  localRotationEulerDeg: { x: 0, y: 0, z: 0 } }

      edgeRight:  { headingDeg: 0,   localRotationEulerDeg: { x: 0, y: 0, z: 0 } }
      center:     { headingDeg: null, localRotationEulerDeg: { x: 0, y: 0, z: 0 } }
    ease: { type: linear, durationMs: 100 }
    blendRadius: 0.15
boxing:
  perHand:
    left:  { scale: 0.75, rotationEulerDeg: { x: 0, y: 0, z: 0 } }
    right: { scale: 0.75, rotationEulerDeg: { x: 0, y: 0, z: 0 } }
  glove:
    states:
      straight: { rotationEulerDeg: { x: 0, y: 0, z: 0 } }
      uppercut: { rotationEulerDeg: { x: 0, y: 0, z: -35 } }
      hookL:    { rotationEulerDeg: { x: 0, y: 0, z: 60 } }
      hookR:    { rotationEulerDeg: { x: 0, y: 0, z: -60 } }
      guard:    { rotationEulerDeg: { x: 0, y: 0, z: -70 } }
```

Bounds compelled by this slice: scale `[0.1,4]`; angles canonicalized into `[-180,180)`. Existing duration/blend/window policies remain unless separately product-approved.

## Composition and Easing

Use one right-handed intrinsic-local XYZ conversion:

```text
qEuler = qZ * qY * qX
```

Flow:

```text
Qworld = QheadingWorld * QbaseLocal * QzoneLocal
```

Boxing:

```text
Qworld = QbaseLocal * QstateLocal
```

Rightmost operation applies first. Mesh mirroring, if needed, is a child visual operation and never a negative scale on the pose root.

Track fixed transition endpoints and evaluate `slerpShortest(startQuat,targetQuat,ease(t))`. Negate target when quaternion dot product is negative and retarget from the pose evaluated at the retarget instant. This removes cadence dependence and ±180 long paths.

## Migration and Legacy Removal

At the YAML/bake boundary only:

- `rotationZDeg` maps to `{x:0,y:0,z:old}`;
- Flow `rotationDeg` maps to `headingDeg`;
- new Flow zone-local XYZ defaults to zero;
- reject mixed legacy/v2 keys.

Runtime validator, equipment records, renderer, and new export accept canonical v2 only. Export/bake/reset emit complete deterministic v2. Scalar aliases are removed rather than retained in production paths.

## Privacy

Live config, per-hand poses, pointer coordinates, and collision evidence remain private graph data. They must stay absent from public snapshots/events, iframe payloads, storage, telemetry, and score records. Static pure geometry/math may be a shared package contract. Privacy tests must recursively reject nested Euler/heading/transform fields.

## Minimal Reproduction

1. Set Flow scale 2 and compare visible endpoint with the fixed 0.75-WU hit capsule.
2. Use a non-center zone whose authored heading differs from motion history; rendered and hit axes differ.
3. Set a base Z offset; renderer rotates while collision does not.
4. Transition Boxing +170°→−170°; current scalar tracker travels roughly −340°.
5. Tick either tracker densely versus sparsely; current results diverge.

## Proposed Verification

- Golden quaternion composition for X, Y, Z, and combined axes.
- Shortest-path ±180, dense/sparse cadence equality, retarget/reset/seek/generation tests.
- Legacy YAML→v2→export→parse→bake deterministic bytes and mixed-key rejection.
- Flow rendered endpoints equal detector endpoints for both hands, scales 1/2, every zone/motion heading, combined XYZ, and GLB/fallback.
- Flow scale 2 / combined XYZ and Boxing scale .75 / combined XYZ use transformed hit-bearing geometry with exact contact-boundary proof.
- Component-isolated glow/model pixel proof from the companion report.
- Direct and cross-origin recursive privacy proof.

## Recommended Fix

Adopt config v2 immediately, remove scalar runtime aliases, move trackers to fixed-endpoint quaternion slerp, and introduce one pure resolved-pose contract shared by gameplay and renderer. Use the same root transform for GLB/fallback/glow. Correct Flow y-axis and timestamp-domain mismatches while touching the tracker.

Derrick confirmed that visual and collision geometry must match. Do not attach browser/PlayCanvas physics bodies or run nondeterministic engine collision. Define deterministic analytic colliders from the same resolved pose used for rendering: a scaled 3D saber capsule from canonical local endpoints/radius, and a scaled 3D glove OBB from canonical local half-extents. At each scored frame, transform these by the pose quaternion/translation and test them against the beat target volume at the judge plane using pure capsule-vs-box and OBB-vs-box math. Direction continuity/timing/chord logic remains unchanged. Include locked config identity in score partition identity.
