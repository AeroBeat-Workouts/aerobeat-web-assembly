# 0.0.68 debug — Off-grid equipment and continuous Flow heading

## Exact observed failure

All four off-grid pointer positions are either rejected before staging or clamped to `(0..1)`, then a null pointer falls back to side defaults. The Flow field also leaves most of the interior and every corner in a semantic `center` fallback: with radius .15, edge influence exists only in small disks around edge midpoints. Near-center/corner motion therefore snaps or fails to turn toward the intended edge blend.

## Expected behavior

Finite pointer positions remain truthful and unclamped beyond every grid side; only `cell/subcell` become null. Equipment remains visible in Flow and Boxing. Orientation intent may saturate at the square boundary, but the nonzero field continuously blends adjacent edge headings around corners. Exact center retains the last stable heading; if no history exists, bootstrap deterministically from the role-side default.

## Execution path

Canvas pointermove → renderer `projectDebugEquipmentAnchor()` ray/plane intersection → current grid bounds rejection and `[0,1]` normalization → assembly clears pointer on null → `testEquipmentInput()` independently clamps/substitutes defaults → evidence currently emits clamped cells → gameplay `measuredColliderSample()` rejects x/y outside `[0,1]` despite body-grid contracts accepting finite off-grid coordinates → canonical pose otherwise accepts finite anchors and renderer staging does not clamp.

Flow orientation calls `zoneDirection()`, which clamps position and weights only five midpoint/disk anchors (four edges plus center). Temporal quaternion slerp is correct; it faithfully interpolates discontinuous/bad spatial targets. Assembly separately picks local Euler by hard nearest-zone classification, another latent snap when local edge rotations differ.

## Most likely root cause

1. Three downstream gates reintroduced grid-bounded semantics: renderer projection rejection, Test helper clamping/defaulting, and gameplay measured-sample `[0,1]` rejection.
2. The five-anchor midpoint-disk model is not a continuous square edge/corner field; its large center fallback dominates normal movement.

## Alternative hypotheses

Renderer frustum clipping, quaternion sign, and strict pose filtering do not explain exact default snaps. Pointer leaving the canvas is adjacent but not the reported within-canvas/off-grid-grid failure. Boxing state classification affects rotation, not positional defaulting.

## Why previous fixes failed

Production body-grid contracts/input already allowed off-grid finite data, but later Test projection/helper/gameplay gates did not preserve it. Existing browser tests require null/reset outside the grid. Existing direction tests cover center→edge midpoint only and explicitly require semantic center fallback; they omit corners and dense center crossings.

## Unknowns

Derrick's “marker/equipment” primarily maps to the visible equipment because shared contracts intentionally hide production wrist markers. If a separate private authoring marker is later desired, it should not alter production marker contracts. Exact-center has a mathematical directional singularity; last stable plus deterministic role-side bootstrap is the chosen behavior.

## Minimal reproduction

Move selected Test hand just beyond each grid edge while still on canvas: projection returns null and equipment resets/disappears in both modes. Move Flow center→corner: heading remains center fallback because corners are outside all midpoint disks.

## Proposed verification

- Projection matrix for x/y `-.25,0,1,1.25` with default/moved cameras: finite ray-plane points remain exact; only viewport/ray/context failures return null.
- Paused/playing Flow/Boxing DOM paths across all boundaries assert exact anchors and continuous equipment visibility.
- Evidence emits finite off-grid x/y with null cell/subcell; analytic capsule/OBB overlap alone decides contact.
- 4,097-sample center→edges/corners/perimeter/outside paths assert exact edges, adjacent-edge corner blend, no center plateau, stable exact center, shortest angular steps, and cadence parity.
- Privacy and Play matrices remain clean.

## Recommended fix

Remove only grid bounds/clamp from renderer projection; preserve validity checks. Preserve finite pointer coordinates in Test helper and retain last valid pointer on genuine projection failure until lifecycle/hand reset. Emit null cells off-grid. Relax gameplay measured collider wrist validation to finite off-grid samples while keeping guard-specific bounds where required. Replace center disks with a four-edge square-radial target: project center→point onto square boundary, blend adjacent edge full quaternions around corners, clamp only orientation input, and retain last stable heading at exact center. Remove hard nearest-zone local Euler selection by blending complete edge targets. Version resolver/config identity semantics; preferably migrate v2→v3 and remove authored center.
