# 0.0.68 debug — Paused equipment authoring

## Exact observed failure

Changing any equipment field during paused Visual Test restarts at song time zero, enters `playing`, starts audio, and restarts RAF. Paused Flow/Boxing retargets also fail to advance because easing uses the frozen gameplay timestamp. Existing browser coverage explicitly expects `frameTimer === 1` after the edit, encoding the regression.

## Expected behavior

An atomic config identity/scoring reseed must preserve transport state, timeline, pause reason, audio state, and stopped RAF. While paused, pointer/config edits must immediately render endpoint equipment poses for both modes without advancing gameplay.

## Execution path

Native `input/change` → `applyEquipmentConfigControl()` → async SHA `commitEquipmentConfig()` → config/identity swap and tracker reset → current active-Test branch calls `startSession("visual_test")`. `startSession()` stops/reseeks/reconfigures, gameplay `requestStart()` sets `playing`, then audio and RAF start. Pausing otherwise stops audio/RAF. One-shot pointer/config renders are supported and paused equipment records are admitted, but Flow/Boxing trackers use frozen `session.timestampMs`; after reset Boxing starts identity→target at t=0.

## Most likely root cause

Two confirmed conflations:

1. Full transport restart is incorrectly used to reseed score/config identity. Gameplay's existing `configureContent(..., {purpose:"visual_test"})` path already clears run truth/generation while preserving active Test state, pause reason, and timeline.
2. Paused presentation shares gameplay-time easing. One-shot paused renders need endpoint authoring semantics (duration 0), not a frozen clock.

## Alternative hypotheses

Audio sync is downstream, not primary; equipment records and renderer already admit paused poses. The async SHA overlap race (`1n48`) is adjacent but not required to reproduce unpause.

## Why previous fixes failed

0.0.67 tests equated “restart scoring” with `startSession()` and explicitly asserted the frame loop restarted. They checked values, not paused transport invariants or rendered Boxing endpoint quaternions.

## Unknowns

A separate presentation-only paused animation clock is possible, but immediate endpoint rendering is the smallest deterministic interpretation of the requested tuning loop.

## Minimal reproduction

Start Test, pause at a target, record state/timeline/audio/frameTimer, then edit any equipment number and await SHA commit. Current result is playing at zero with active RAF. Independently, pause and retarget a nonzero-ease Boxing state; pose remains at interpolation t=0.

## Proposed verification

Real Chromium captures gameplay generation/state/timeline/pause reason, audio state/clock, assembly session generation/RAF, and private rendered quaternion/config identity. Edit Flow base/heading and active Boxing state while paused. Require transport/time/audio unchanged, RAF zero, score truth/history reseeded, and endpoint poses/config identity changed immediately with no public/storage/cross-origin leak.

## Recommended fix

Replace active-Test `startSession()` in config commit with the existing preserve-Visual-Test `configureGameplayFromContent(false,"visual_test")` reseed. Tick Flow/Boxing trackers with duration 0 while paused, then resume normal authored duration from that endpoint. Add canonical no-op suppression and evaluate/fix `1n48` while changing the commit queue.
