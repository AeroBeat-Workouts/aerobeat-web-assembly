# 0.0.64 off-grid wrist calibration restart

## Exact Observed Failure

Derrick reports that raw 0.0.63 still pauses/restarts calibration when his wrists move outside the calibrated range.

The current input unit suite proves only a **single** off-grid wrist with bent/released elbows. A new minimal diagnostic reproduces the physical large-swing shape with both wrists confidently outside the original grid while shoulders/elbows are horizontally extended:

```text
before: calibrationId physical-offgrid-1, state calibrated, gameplayPaused false
6500: calibrationId physical-offgrid-1, state recalibrating, readiness calibration_required,
      wrist raw x = -0.333 / 1.333, cells null
8500: calibrationId physical-offgrid-2, state cooldown, readiness calibration_required
```

The service does not set `tracking.gameplayPaused=true` in this direct fixture, but it immediately enters `recalibrating/calibration_required`, and after the 2 s hold commits a new calibration generation. Assembly/gameplay safety presents that as calibration interruption/restart and freezes normal play/audio.

## Expected Behavior

In a healthy calibrated session with unchanged camera source:

- confident off-grid wrists remain staged with finite coordinates and null scoring cells;
- ordinary large outward swings do not enter recalibration, require release, change calibrationId/bounds, or interrupt gameplay;
- deliberate in-play recalibration remains available without weakening fail-closed initial/source-change recovery.

## Execution Path

1. Measured frame keeps all required anchors confident, so loss/freeze logic does not fire.
2. `updateCalibration()` calculates `qualified = allRequiredAnchorsVisible && qualifiesTPose(landmarks)`.
3. `qualifiesTPose()` examines body geometry only; it does not distinguish an intentional calibration gesture from a large outward Flow swing or whether wrists are already outside the active calibrated bounds.
4. With healthy calibration, released gate satisfied, and horizontal shoulders/elbows/wrists, `qualified` starts `holdStartedAt`, changes state to `recalibrating`, and readiness to `calibration_required` immediately.
5. A 2 s continued outward pose commits new bounds/calibrationId and re-arms the release gate.
6. Assembly/gameplay safety responds to calibration-required state by interrupting active gameplay.

## Most Likely Root Cause

The prior D1 fix addressed off-grid **anchor staging** but preserved unrestricted in-play T-pose refire. A large two-arm outward motion is geometrically indistinguishable from the existing T-pose trigger. The regression oracle used only one off-grid wrist plus deliberately non-T-pose elbow geometry, so it never exercised the physical two-arm boundary case.

This is not a renderer/contract rejection: the diagnostic shows both off-grid wrist coordinates are finite and cells are null as intended. The state changes before renderer concerns matter.

## Alternative Hypotheses

1. **Camera source identity/aspect churn:** still plausible in some physical incidents because any identity change invalidates calibration, but it is not required to reproduce Derrick's symptom; the fixture uses one stable source and still restarts calibration.
2. **Confidence loss:** contradicted by 0.95 confidence on every anchor and `gameplayPaused=false` in the reproducer.
3. **Cross-generation evidence rejection:** occurs after a calibration commit if evidence is stale, but the service intentionally clears it and the interruption begins earlier at T-pose qualification.
4. **Contract rejection of off-grid anchors:** repaired in 0.0.63 and contradicted by valid finite diagnostic anchors.

## Why Previous Fixes Failed

- The previous test case moved only the left wrist and used `releasedChanges` for elbows/right wrist, explicitly avoiding T-pose qualification.
- The previous plan intentionally preserved ordinary in-play T-pose refire and treated it as a required negative control, without resolving gesture ambiguity against large Flow swings.
- Renderer/contracts changes fixed visibility but cannot prevent input's calibration state machine from interpreting the body pose as recalibration intent.

## Unknowns

- Whether Derrick's exact physical event also includes source/aspect changes. Add private test/profile evidence for source identity to distinguish secondary causes.
- Whether deliberate healthy-session recalibration should remain gesture-only or require a UI arming action. The smallest compatible fix below retains gesture refire when wrists are inside the current grid and preserves unrestricted T-pose recovery after source invalidation.

## Minimal Reproduction

1. Create and complete initial T-pose calibration.
2. Release to a neutral/bent-arm pose until healthy calibrated readiness.
3. With the same source and full confidence, extend both arms horizontally so both wrists are beyond the calibrated left/right bounds.
4. Current result on the first frame: `calibration.state = recalibrating`, `readiness = calibration_required`; after 2 s, calibrationId changes.

## Proposed Verification

Add a fail-before input oracle with three rows:

1. Healthy calibrated + both confident wrists off-grid + T-pose-like horizontal body for >2 s → calibrationId/bounds unchanged, state calibrated/countdown, no pause/fresh requirement, wrists finite/null-cell.
2. Healthy calibrated + deliberate in-grid T-pose after release → existing refire still commits and requires physical release.
3. Source-changed/fresh-required + T-pose that is outside old bounds → recovery still commits new bounds (old-grid containment must not block fail-closed recovery).

Then drive row 1 through assembly/gameplay to assert session/audio never enter calibration pause.

## Recommended Fix

For **ordinary healthy-session refire only** (`calibrationId !== null && !freshCalibrationRequired && !trackingPaused`), require the T-pose's left/right wrists to lie within the active calibrated bounds before treating it as a recalibration hold. Compute this using the same `cameraPreviewToAthlete()` + `normalizeAgainstBounds()` path used for anchors.

Do not apply the containment guard to initial calibration or source-change/fresh-required recovery, because those flows must be able to establish replacement bounds. This addresses the gesture ambiguity at its source without weakening safety.

## Post-fix result

Input commit `fe9b92e` adds the admission guard only to ordinary healthy-session T-pose refire: both wrists must remain inside the active calibrated bounds (with machine-epsilon boundary tolerance) before a replacement hold may start. Initial calibration and fresh/source-invalidated recovery bypass old-bound admission and can still establish replacement geometry.

The focused input oracle holds bilateral confident horizontal off-grid wrists for 2.25 s and proves unchanged calibration ID/bounds, calibrated/countdown readiness, no gameplay pause/fresh requirement, and finite non-scoring wrists with null cell/subcell. Controls prove deliberate in-grid refire and source-change recovery still commit. Full input `npm test` passes. The assembly mobile browser row then drives one bilateral off-grid T-pose-like frame during active play and proves gameplay remains playing/calibrated before a subsequent deliberate in-grid T-pose still enters the existing recovery path. This closes the reproduced stable-source bug; physical source/aspect churn remains a distinct fail-closed invalidation path and retest diagnostic, not something this fix suppresses.
