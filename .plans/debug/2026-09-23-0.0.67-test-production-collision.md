# 0.0.67 Visual Test production collision diagnosis

## Exact Observed Failure

With Visual Test running, equipment preview enabled, one mouse hand selected, and automatic GREAT/MISS disabled, moving visible equipment through a beat produces no gameplay judgement, score, combo, miss, or production hit aftermath.

Direct code evidence:

- Assembly deliberately omits `input` on every `visual_test` gameplay frame.
- The Test equipment input is renderer-shaped and lacks production evidence identity, calibration, provenance, timestamps, source/frame IDs, cells, and history.
- Gameplay commits input and runs Flow/Boxing live evaluation only for purpose `play`.
- Visual Test begins with null calibration and bypasses safety.
- Judgement records/contracts hard-code purpose `play`.
- Renderer target projection ignores real judgements for Visual Test.

## Expected Behavior

Derrick selected full gameplay truth. Only when Visual Test is playing, automatic feedback is off, and a mouse hand is active, strict synthetic evidence must route through the same production coordinator logic as Play. Valid collisions produce ordinary hit judgements, score, combo, and aftermath; invalid/late beats produce ordinary misses. Test remains unranked, local-only, and non-persistent. Paused Test does not advance outcomes.

## Execution Path

Current:

1. Pointer movement maps through camera-aware renderer projection.
2. Assembly latches a normalized Test wrist.
3. Test equipment records render, but assembly omits gameplay input.
4. Coordinator advances audio timeline only.
5. Purpose guards skip evidence capture and Flow/Boxing evaluators.
6. Auto feedback off leaves targets pending until they cull.

Required:

1. Assembly builds strict production-shaped synthetic evidence from Test wrists, active timeline, and monotonic interaction identity.
2. `advance()` receives that evidence plus an explicit exact Visual Test production-interaction authority.
3. Coordinator commits input without Play camera/calibration acquisition.
4. Existing production capture, Flow/Boxing evaluation, miss finalization, judgement, scoring, combo, and aftermath paths run unchanged.
5. Renderer admits real Test judgements while synthetic feedback remains mutually exclusive.

## Most Likely Root Cause

0.0.66 intentionally made Test wrists renderer-only and locked zero gameplay truth. The new request reverses that invariant. Four coordinated gates—not a missing collision formula—block it: assembly frame omission, gameplay input-purpose guard, gameplay evaluation-purpose guard, and Play-only judgement/render contracts.

## Alternative Hypotheses

1. **Feedback checkbox suppresses scoring:** rejected; it gates renderer target/aftermath synthesis only.
2. **Forward existing Test equipment input to gameplay:** rejected; it is not a valid production input/evidence snapshot.
3. **Copy collision helpers into assembly:** rejected; misses, chords, ordering, histories, scoring, hazards, and snapshots are coordinator-owned.
4. **Broaden all Visual Test sessions globally:** rejected; automatic feedback would double outcomes and ordinary Test behavior would change silently.
5. **Boxing needs a new swept-volume algorithm:** rejected for this slice. “Same logic” means the current production evaluator: current-frame overlap plus prior/current direction continuity.

## Why Previous Fixes Failed

No prior scoring fix failed. 0.0.66 correctly implemented the former requirement that Test authoring remain renderer-only and non-scoring. Its tests explicitly require zero Test judgements and score partitions. That behavior is now intentionally superseded only under a narrow interaction authority.

## Unknowns Resolved

- **Boxing semantics:** preserve the current production evaluator rather than inventing segment-swept contact.
- **Activation:** arm only strictly future event centers when production interaction becomes active; do not restart Test and do not retroactively miss notes already presented synthetically.
- **Visible wrists:** both visible wrists remain valid evidence so visual equipment and hit geometry stay coherent; epoch/history reset prevents a newly selected hand or pointer discontinuity from creating a swept hit.
- **Hazards/guards:** unchanged production evaluator scope applies. No synthetic nose is invented; two-hand logic uses the visible Test wrists.

## Minimal Reproduction

1. Start Visual Test with Flow or Boxing collider content.
2. Enable equipment preview, select Left or Right, disable automatic feedback.
3. Move equipment through an eligible target inside its timing window.
4. Observe `judgements=[]` and `scorePartitions=[]`; after the late boundary the target disappears without a production miss.
5. Control: equivalent valid Play evidence commits the normal outcome and score.

## Proposed Verification

- First characterize current parity: identical evidence scores in Play and remains empty in ordinary Test.
- Add explicit interaction mode and compare normalized Play/Test production outcomes and score records except truthful purpose/session identity.
- Cover Flow capsule/direction/chords/strict late boundary, Boxing straight/hook/uppercut/guard/current-overlap behavior, hit→combo→miss reset→hit, bombs/hazards, one aftermath per hit, and duplicate prevention.
- Cover activation mid-song, hand switch, pointer invalidation, pause/resume, seek, hidden/terminal/detach, stale/rollback/duplicate frames, lease loss, and baseline seeding.
- Prove auto feedback on retains zero gameplay outcomes and no synthetic/real double outcome is possible.
- Direct and genuine-cross-origin browser proof may expose ordinary Test judgement/score truth while recursively rejecting private pointer/evidence/config/camera fields and all persistence writes.

## Recommended Fix

Extend gameplay `advance()` with one optional exact authority record, e.g.:

```js
interaction: {
  schema: "aerobeat/visual_test_interaction",
  version: 1,
  mode: "production_judgement",
  epoch,
  activationTimelineMs
}
```

Accept it only for `visual_test`, Flow/Boxing collider rulesets, playing state, and a strict valid input snapshot. Absent authority preserves 0.0.66 behavior byte-for-byte. Coordinator owns epoch transitions, clears/seeds history, excludes event centers at or before activation, and routes through existing production evaluation. Judgements become truthfully purpose `visual_test`; contracts admit that purpose. All Test score partitions are unranked/local-only and no persistence API is added.

Assembly derives authority only from auto feedback off + selected mouse hand + valid scoring evidence, creates monotonic frame/source/calibration identities, and increments epoch on every discontinuity. Target projection admits real Test judgements; synthetic target/aftermath branches remain off while production interaction is active.
