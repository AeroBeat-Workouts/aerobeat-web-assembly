## Why this is not a boolean in production

The vendored Tasks Vision 1.0.1 Worker adapter already accepts `delegate: gpu-webgl`. But the *production* `createLockedProductionCvService` explicitly rejects WebGL execution telemetry and reports `providerId: cpu-wasm`; merely changing the adapter flag fails the locked guard and would mislabel results. Google’s default sample uses GPU then falls back to CPU on failed GPU initialization, Lite float16, Tasks Vision 1.1.0, different thresholds and cadence. Its rolling inference number is not a sustained 60-second pose rate. Preserve all production guards unchanged. Use a **private experimental service** mirroring the same one-VideoFrame-in-flight, ≤15/s admission, timing and counter semantics with a delegate-aware validator; unit-test CPU-service parity. Any difference between experiment and baseline must be disclosed. No change to chart, game, scorer, output model, source constraints or public routes.

This is a plausible ordinary-worker external request, not proof that video frames or landmarks are sent; the specific payload/occurrence remains unobserved. The first GPU preview had no response CSP, unlike the separately hardened CPU friend preview, so the proposed private switchover is **NO-GO** until Worker egress is guarded and rechecked. Bead `vazw` is a hard dependency of route `oqwf`.

**Execution path:** GPU page's own manifest/model/WASM fetches are same origin; the vendored JS is loaded in a dedicated classic Worker, whose network policy comes from the Worker script's **own HTTP CSP response**, not merely the HTML document. **Leading risk/root cause:** no `connect-src` response header on the GPU preview means a possible logger POST is not prevented; no live POST has yet been observed. **Alternatives/unknowns:** logging may be gated/empty and never emit in tested browsers, but static graph-start/close call sites plausibly reach it; bounded runtime request capture over startup, full ≥60s window and close resolves occurrence in Chromium, not every phone. **Minimal verification:** keep model/WASM/Worker bytes signed, add to only the new GPU preview config `Content-Security-Policy: connect-src 'self'` plus no-referrer/nosniff on HTML and Worker; verify headers, real GPU Worker still infers and preview forced CPU still infers, document+actual Worker harmless third-party `fetch` are denied; record actual Worker-inclusive request origin/method through ≥65s and disposal.
