## W0 Diagnosis — CONFIRMED root causes (code-level, parent-verified)

- **B1 (tolerance not glued to center):** `colliderOverlayObjects` (renderer `gameplay-scene-model.js`) anchors at `iconRenderPosition`, whose Z is `movingZ = timestampToWorldZ(beatCenterMs, nowMs, worldUnitsPerMs)` — a *separate* Z from the note icon's rendered position (`targetPositions` returns only `{x,y}`; the icon's Z is computed separately in `targetObjects`). So the cone/square sit at a different Z than the note's white-cube center ("in front of the beat"), and the Z source switches at the hit/miss boundary ("jumps ~1s later"). **Fix:** anchor the overlay at the icon's *actual* rendered position (same x/y/z the icon uses), not a recomputed Z.
- **B2 (collider doesn't deactivate on resolve):** CONFIRMED — `colliderOverlayObjects` iterates **all** `sorted` targets with **no** hit/miss/aftermath gating, so the cone/square persist after the beat resolves. **Fix:** skip targets whose state is resolved (hit/miss) — i.e. the same gate the icon uses (`targetVisible`/`aftermathHandoff`).
- **B3 (aftermath = two white spheres):** CONFIRMED — `aftermathObjects` uses `ASSET.circle` (`any-note/outlined-circle-v1`) for the flow slice halves (`AFTERMATH_FAMILY_ASSET.flow = ASSET.circle`) and `ASSET.arrow` for punches, with no gray tint. **Fix:** render the aftermath as a **cut-in-half of the note's actual asset** (arrow for directional, orb for directionless), **grayed out** when hit.
- **B4/B5 (half-circle regression):** CONFIRMED same root as B3 — the "cut-in-half circles" are the aftermath slice (two clip-plane halves) rendered with `ASSET.circle` for flow notes, now persistent across frames (0.0.55 W2 aftermath-persistence made it show for the live-7). The affected notes are the most-recent aftermath entries (the live-7 cap), colored like the arrows they should be. **Fix:** the aftermath must use the note's actual asset (arrow/orb), cut in half, grayed — i.e. the B3 fix resolves B4/B5. (Verify no separate Test→Play state leak remains after the B3 fix.)
- **B6 (song-swap resets mode to Flow):** CONFIRMED (subagent clean control) — direct `selectGameplayAxes` restores Boxing, but the menu song-swap path never calls it (falls back to the default Flow ruleset). **Fix:** preserve the active Flow/Boxing mode across a song change (re-apply `selectGameplayAxes` with the current ruleset/recipe on song-swap).
- **B7 (hide "locked" message):** CONFIRMED — the string is `session-coordinator.js:410`: `"Boxing Collider reach and guard settings are locked for the complete run"` (the `boxing_collider_settings_locked` error). **Fix:** stop surfacing this error in the UI (it's internal; the settings aren't user-exposed).
- **B8 (Boxing vignette missing):** CONFIRMED — `projectHazardContactEvents` (assembly `gameplay-frame-effects.js`) only reads Flow `obstacleOutcomes` + `hazardOutcomes` (kind "bomb"/"wall"); Boxing collider collisions produce neither, so `hazardContactActive` is never set for Boxing and the vignette never fires. **Fix:** emit the hazard-contact state for Boxing collider collisions too.
- **B9 (Boxing hit-corpses):** CONFIRMED — punches always use `ASSET.arrow` (even straight punches from circular/orb "any" notes, which should keep the orb shape) and fall fully white (no gray tint). **Fix:** use the note's actual asset (orb for directionless, arrow for directional) + gray tint; keep the launch/fly-away behavior.

## B10 (NEW, from 0.0.56 retest) — aftermath slice clip-plane contaminates the shared material + wrong cut direction
Derrick's 0.0.56 retest (Backstreet Boys "Incomplete" Normal, Test playback, screenshots) showed **LIVE arrows/orbs cut in half** (not just the aftermath), with the cut in the wrong direction.

**Root cause (confirmed):** the aftermath "cut-in-half" effect uses a clip-plane (GLSL discard blocks injected via `installSliceClipBlocks` into the material's `shaderChunks.glsl` + `material.update()`). `material.update()` flags the chunk map dirty, regenerating **every variant including the shared opaque "standard" program** with the clip blocks — so the clip-plane (meant only for the aftermath slice halves) contaminates the **shared material**, clipping the **live notes**.

**Intended cut direction (Derrick's spec):** for a hit note, the two halves are a **vertical cut down the middle (left/right halves)**, and the two sides **fall while separating to the left and right**. E.g. a DOWN arrow: a cut in the horizontal middle (vertical center) running down to the bottom; the left and right halves fall apart. The current clip-plane is a **local-Y cut (top/bottom)** — the WRONG direction. It must be a **local-X cut (left/right)**.

**Fix (B10, renderer):**
1. Isolate the clip-plane from the shared material (deep-clone `shaderChunks.glsl` or a distinct program cache key) so live notes are NOT clipped.
2. Change the clip from local-Y (top/bottom) to local-X (left/right) so the halves match Derrick's spec.
- e2e-proof: live notes render FULL (no clip) when the aftermath slice is present; the aftermath halves are left/right (vertical cut), not top/bottom.
