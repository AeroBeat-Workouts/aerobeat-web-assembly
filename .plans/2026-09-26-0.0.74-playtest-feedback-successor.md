## P0 — blocking bugs (fix first)

### T1. Tracking-loss no-pause (B1.1 re-open) — REAL-WORLD broken
Walk out of frame mid-song (boxing AND flow) → gameplay PAUSES but music continues, then on re-establish the gameplay jumps forward (instant seek) and beats flow. It should CONTINUE (F4 anchor-freeze: markers freeze, beats+music continue, no pause, no seek).
- The 0.0.74 e2e (`validate-boxing-tracking-freeze.js`) passed but proved the WRONG thing — it did not exercise the real tracking-loss → pause path. The real path is in the input service + assembly pause logic.
- **Action:** trace the real tracking-loss path (input `tracking_lost` → assembly → `gameplayPaused`), find why it pauses + seeks, fix so it enters the tracking freeze (no pause, no seek). Add a REAL e2e that drives an actual tracking-loss event (not a synthetic pose bridge) and asserts no-pause + no-seek.

### T2. Rumi/Jinu flow-interval still throws (B1.6 / Bead 072b)
`Flow interval timestamps must have positive duration and start at center` — `session-coordinator.js:1852 validateFlowInterval`. Song won't start (play or test). The content-authoring emits flow intervals whose `startTimestampMs !== centerTimestampMs`.
- **Action:** fix the content-authoring flow-interval emission so start == center (and end > start) for the real Rumi/Jinu chart. Verify with the real BeatSaver chart (not just a synthetic fixture).
