# 0.0.73 — Disable mid-game T-pose recalibration gesture

> **STATUS (2026-09-25): SHIPPED in immutable raw 0.0.73 (served on 5173). Awaiting Derrick's physical playtest to confirm the off-grid pause no longer reproduces; Bead `aerobeat-web-assembly-bniy`.**

## Intake (Derrick)

> "I playtested 0.0.71, still able to recreate the pause for calibration bug. … it's me holding my arms out at a full stretch horizontally (similar to a TPose). My guess is that the calibration/tpose logic is firing when it shouldn't be (mid-game) and that's causing the remaining bug. Check if that logic is still activated and disable it if it is (we will leave calibration to a pause screen option / when play mode starts and disable the gesture activating it at other times)."

## Diagnosis (confirmed)

The `0×0` camera-identity fix (0.0.71) was a legitimate robustness improvement but was **not** the actual trigger. The real path:

1. Mid-game T-pose → input `updateCalibration` → `ordinaryHealthyRefire` (`calibrationId && bounds && !freshCalibrationRequired && !trackingPaused`) true → `qualified` true (wrists inside calibrated bounds) → 2000ms hold → **commits a new calibration** → mints a fresh `calibrationId`.
2. Coordinator `commitInput` sees `nextCalibrationId !== calibrationId` with `readiness = "calibration_required"` → `freshCalibrationRequired = true` → `safetyReady = false`.
3. `enforceSafety` → `enterTrackingPause()` → `paused_tracking` → the pause + resume countdown Derrick saw.

So a T-pose held during a move (e.g. a Flow stretch) was committing a recalibration that paused the game.

## Design (per Derrick)

- **Disable the T-pose recalibration gesture during active gameplay** (`playing` / `countdown`).
- **Keep** initial calibration (when play mode starts, `bounds === null`) and pause-screen / recovery recalibration (after `resetCalibration`) enabled.

## Implementation

- **Input** (`aerobeat-web-input` `body-grid-service.js`):
  - New state `midGameRecalibrationEnabled` (default `true`, backward-compatible).
  - New public method `setMidGameRecalibrationEnabled(enabled)`.
  - `updateCalibration`: `midGameGestureBlocked = ordinaryHealthyRefire && !midGameRecalibrationEnabled`; the gate only suppresses the healthy mid-game refire — the initial (`bounds === null`) and recovery (`freshCalibrationRequired`/`trackingPaused`) paths are unaffected.
- **Assembly** (`aerobeat-web-assembly` `index.js`):
  - New state `this.midGameRecalibrationDisabled`.
  - In `runDisplayFrame`, `midGameActive = state === "playing" || state === "countdown"`; call `graph.input.setMidGameRecalibrationEnabled(!midGameActive)` on change.

## Oracles

- `aerobeat-web-input/scripts/validate-body-grid-service.js` — gate ON commits a mid-game refire; gate OFF does not commit / does not pause / does not require fresh calibration; initial calibration and recovery recalibration still commit with the gate off.
- `aerobeat-web-assembly/scripts/validate-aero-game-assembly.js` — gate-wiring source oracle (state tracking, playing/countdown detection, `setMidGameRecalibrationEnabled(!midGameActive)` call).
