### F2 — boxing corpse spawns right of the hit spot (ROOT CAUSE CONFIRMED)
- **Two different X conventions for the same physical columns:**
  - **Wrist/judge space:** `measuredColliderSample` (flow-collider-collision.js:~75) maps the calibrated body-grid anchor to `sx = 4·x_norm − 0.5` → column centers at **x = 0, 1, 2, 3**. The judge plane uses the same convention: `targetCenterForPlacement(placement) = {x: placement % 4, …}` (flow-collider-collision.js:78) and `boxingColliderTargetCenter` (boxing-collider-collision.js:121-123).
  - **Presentation space:** the visible note icon renders at `worldPositionForCell(cell)` → `x = columnX[col] ∈ {−1.5, −0.5, 0.5, 1.5}` (gameplay-scene-model.js:44,109-113); the boxing_collider `targetPositions` branch keeps that X and only swaps Y for the reach row (:392-404); at hit, `iconRenderPosition` pins `z = 0` (:374-376). Collider overlays anchor at the same icon position (:822-833) — so the note's disappearance point is (columnX[col], reachRowY, 0).
- **Consequence:** for EVERY cell the corpse (B15: `punchCellToRenderedPositionZ0` → x = `cell % 4`) spawns **exactly +1.5 WU to the right** of where the visible note disappears. Computed screen space (camera {0.05,1,5}, vfov 48°, 844×390 canvas → 87.6 px/WU at z=0): **constant +131.4 px right for all 12 cells** (≈ +303 px on a 900 px-tall viewport); Δy = Δz = 0 (Y and Z already match). This is Derrick's "a few units to the right" — 1.5 world units.
- **B15's premise was wrong — and B15 regressed X while fixing Y.** Pre-B15, `gridCellToWorldZ0` already gave the note-matching X (columnX) and only the top/bottom-row Y jumped (old full-grid rowY 2/1/0 vs reach-row Y, ~0.75 WU). B15 moved boxing to `punchCellToRenderedPositionZ0`: Y fixed, X changed from columnX to `cell % 4` on the false premise that "the renderer renders the punch icon at x = placement % 4" (that is the JUDGE plane, not the icon). B15's unit tests compared corpse-vs-judge-plane (identical by construction) and pinned the WRONG values (validate-gameplay-frame-effects.js B15 block).
- **The canvas-freeze artifact (bead `iy23`) is explained — it was never a freeze:** the B15 real-pixel oracle built events with `type`/`spatialTarget` at TOP LEVEL and NO `authoredBeat` → `projectSessionTargets` (which reads `authoredBeat.type`, session-render-projection.js:100) fell back to "note" → punches projected as FLOW targets with `cell: null` → the renderer's boxing_collider branch hit the LANE fallback (x=−0.9 for every left-hand punch) → pixel-identical frames between punches. Additionally the oracle's expected note position used the same false `cell % 4` identity (self-referential), had one fixed baseline mixing note/feedback pixels into the diff, and flipped Y twice. Re-run this session: runs to completion, all renders advance, Δ≈48.4 px (a mixed-centroid artifact, not the true 131 px).
- **Fix (W2):** in `punchCellToRenderedPositionZ0` (gameplay-frame-effects.js:145-156) replace `const x = cell % 4` with `const x = gameplayWorldGrid.columnX[cell % 4]` (import from `@aerobeat/web-renderer` — dependency already exists, gameplayWorldGrid exported from the package root); keep Y (`boxingColliderRowY`) and z=0 (both already correct); rewrite the B15 comments (renderer world = judge x − 1.5). Flip the B15 unit-test pins to the renderer truth (cell 4 → {−1.5,1,0}, cell 0 → {−1.5,1.25,0}, cell 8 → {−1.5,0.75,0}, cell 6 → {0.5,1,0}, wide-reach rows, test-mode case).
- **Real-pixel proof (rework of the B15 oracle, wired into `test:browser`):** production-shaped chart (events with `authoredBeat.{type,hand,spatialTarget}` + gate assertion that the projected target is `kind==="punch"` with `cell` set — catches the shape-mismatch class that caused the "freeze"); ground-truth disappearance pixel READ FROM THE RENDERER (icon world position from the scene model + `camera.worldToScreen`, no Y flip); per-frame same-nowMs baseline (same frame minus the aftermath entry → corpse-pure diff); assert at t=0..16 ms (launch is sub-pixel in that window) with ~6 px tolerance vs the 131 px error; multi-cell coverage (right column + top/bottom reach rows at non-default reach); frameCount + pixel-hash sanity guards against any future real freeze.
- **Closes bead `iy23`.** Longer-term (separate bead, non-blocking): move the 4×3 grid constant to `@aerobeat/web-contracts` so judge and presentation import one truth (presentation grid living in the renderer is the drift risk that produced B15).

### F4 — tracking loss pauses the song (DESIGN CONFIRMED, subagent report)
- **Current chain:** loss detection in `body-grid-service.js` (3 loss anchors nose/left/right-wrist, conf ≥ 0.5; three trigger paths: 3 consecutive low-conf frames + 750 ms window; silent gap ≥ 750 ms; no-frame `advanceTime` ticks at ≥15 Hz). All call `triggerTrackingPause` → `invalidateCalibration("tracking_lost")`: `readiness="paused_tracking"`, `freshCalibrationRequired=true`, `latestEvidence=null`, `resetMeasuredHistories()` (anchors cleared → markers vanish). Coordinator `enforceSafety` → `state="paused_tracking"` → audio pause + `seek`; resume demands `freshCalibrationRequired` cleared — partial auto-recovery (300 ms hold) usually fails → **full T-pose** (2000 ms).
- **Design (owner spec):** mid-run tracking loss while already calibrated → **freeze, don't pause**:
  - New `anchorsFrozen` flag on the tracking safety snapshot (contracts typedef + validator).
  - `body-grid-service.js`: calibrated + loss → `anchorsFrozen=true`; keep `latestAnchors` (markers freeze at last position); `latestEvidence=null` (no new evidence minted); readiness stays `"countdown"`; `trackingPaused`/`freshCalibrationRequired` stay false. Uncalibrated loss and source-change loss keep the old full-pause + T-pose path. Passing sample clears the freeze on the very next good frame — no gesture, no hold.
  - `session-coordinator.js`: **no functional change** — `safetyReady` stays true → state stays `"playing"` → audio keeps playing, timeline advances. `paused_tracking`/`tracking_resume` remain for source-change/full recalibration only.
  - `index.js` (assembly): `gameplayCursorRecords` gate bypasses suppression while `anchorsFrozen` (the single edit that makes markers freeze instead of vanish); telemetry + optional non-blocking "tracking lost" cue.
  - Renderer: no change (renders the cursors it's handed).
- **Ghost-hit safety (proven):** every scoring path rejects evidence older than 150 ms (`maximumColliderSampleFreshnessMs`) and swept contacts need two strictly-increasing samples — a frozen marker can never register a new hit. During the freeze, notes finalize as **miss** naturally (combo resets), bombs/walls finalize `unevaluated_tracking` (no penalty). Derrick accepted "keep gameplay running"; these are the natural consequences — flagged as explicit decisions below.
- **Tests:** extend `aerobeat-web-input/scripts/validate-body-grid-service.js` (freeze enter/exit, hysteresis, anchor retention, no T-pose on resume, uncalibrated still pauses, source-change unchanged) and `aerobeat-web-gameplay/scripts/validate-gameplay-session.js` (state stays playing across a freeze, notes miss with stale/no_input, zero hits, bombs/walls unevaluated). Deterministic, no camera.
- **Closes bead `tm4m`** (diagnose mid-gameplay tracking loss / T-pose re-entry) once implemented.

### F1 — flow corpse still gray (B13 re-open; ROOT CAUSE CONFIRMED — two independent causes)
- **(1) The corpse fill is the NOTE'S REAL FILL, 0.92-lerped to grayscale — and this song's note fill is a PALE BeatSaver palette color.** Real flow events always carry `appearanceColor = palette.left|right` (content-runtime.js:465; flow beats always have `hand` + boolean `requiresDirection`, converter.js:325 / package-content.js:423-429). The assembly threads it onto the aftermath entry (B11b: gameplay-frame-effects.js:398/435-436) — so B13's role-from-hand is only the FALLBACK (used when `appearanceColor` is ABSENT); in the real pipeline it is always present and the fallback never fires. The renderer desaturates the real fill: `aftermathCorpsePartColor` note_fill branch (renderer-facade.js:368-372) = 0.92 lerp of `appearanceColor ?? roleColor` toward luma grayscale (`AFTERMATH_CORPSE_DESATURATION=0.92`, gameplay-scene-model.js:89). Computed: pale saber color `#A8C8E8` → corpse (193,196,198), b−r≈5, luma≈196 — **exactly the observed pale gray/lavender ~180-200**.
- **(2) The 0.92 desat is too strong to ever read "clearly colored by hand":** even the SATURATED default `#2693FF` collapses to (124,133,141) = blue-GRAY (spread 17); `#39C96B` → (155,167,159) (spread 12).
- **Why the B13 oracle passed:** its fixtures only tested (a) no-appearanceColor (saturated role fallback) and (b) `appearanceColor:#2693FF` (the saturated default) — never a pale/near-white fill like the real song's. And its assertions REQUIRED a desaturated result (`bMinusR>12`, `55<luma<160`, `meanSat<40` — "strongly desaturated, tint not saturated" = literally asserting a gray-ish corpse as PASS). The real pale fill (luma ~190-220, meanSat ~5) is outside those bands — a faithful fixture would have FAILED. Same "code test ≠ e2e proof" failure mode, root: fixture shape + assertion polarity both matched the wrong path.
- **Why boxing reads "colored" (OPEN — needs the W1 probe):** the corpse color path is SYMMETRIC — flow and punch entries both carry the same shared-palette `appearanceColor` and render through the same `aftermathCorpsePartColor` (flow via the slice-variant path, punch via the whole path). The code does NOT structurally make boxing bluer. Best explanation: perception — a boxing punch is one larger solid arrow sitting next to its saturated live note + hit flash, while a flow hit is two small falling halves; and/or the boxing session hit the more-saturated palette side. **W1 step 0: runtime probe** — dump "Incomplete" Normal's `effectiveNotePalette` (left/right hex) from the served app's content runtime + read one real flow-vs-boxing corpse fill side by side in real pixels. That resolves both the exact palette hex and the paradox before any constants are committed.
- **Fix (W1, renderer):**
  - `aftermathCorpsePartColor` note_fill branch (renderer-facade.js:368-372): if the note's real fill is near-achromatic (channel spread < threshold, start ≈0.18 sRGB), substitute the saturated HAND color (`roleColor(role)` — B13 already resolves flow/punch roles to left/right) as the desat source before the lerp. Saturated fills keep their own tint (B11b intent preserved); pale/gray fills become the hand color.
  - Companion: lower `AFTERMATH_CORPSE_DESATURATION` from 0.92 → ~0.55 (UNCALIBRATED start; the oracle + the probe pin it) so surviving color reads as clear blue/green instead of a gray wash. At 0.55: `#2693FF`→(98,147,195) clear blue, `#39C96B`→(93,157,115) clear green.
  - Assembly unchanged (B13 threading is correct). Optional deeper fix NOTED, not this cycle: `colorTokenToRgba` returns sRGB but it is set as LINEAR diffuse (GPU gamma lightens mid-tones further) — true color-space fix = linearize before the lerp (broader change).
- **Oracle (rewrite of validate-0.0.59-flow-corpse-color-pixels.js):** fixtures with a PALE appearanceColor (`<PALE>` = the real import hex from the probe; `#A8C8E8` stand-in only if unavailable): `flow_pale_left`/`flow_pale_right`/`flow_saturated_ctrl` (`#2693FF` regression guard)/`punch_pale`. Assertions INVERTED to require saturation: left fill `bMinusR>30 && spread>25 && 70<luma<215`; right fill `gMinusB>25`; flow-vs-punch parity `|ΔbMinusR|≤16`. Fails pre-fix (`#A8C8E8` → b−r≈5, spread≈5), passes post-fix.
- **Collateral:** if the desat factor changes, `validate-0.0.58-aftermath-pixels.js` (B11b) asserts a specific desaturated fill and must be rebaselined in the same lane.

### F3 — straight punches hittable by either wrist (ROOT CAUSE CONFIRMED + REPRODUCED)
- **Root cause (reproduced end-to-end on current code):** straights are **overlap-only** and their inflated footprint **permanently covers the player's raised guard fists**:
  - `boxingAuthoredDirection()` returns `undefined` for straights (boxing-collider-collision.js:146-151); `matchesBoxingAuthoredDirection()` short-circuits to `true` for `direction === undefined` (:284-289), applied at session-coordinator.js:1000. Hooks/uppercuts require ≥0.05 WU directed travel in a ±45° cone (flow-collider-collision.js:53,149-158) — a stationary fist can never satisfy that; it trivially satisfies overlap.
  - Contact = pure position+timing overlap, half-extent `0.375 + colliderRadius(0.12) = 0.495` WU, against `boxingColliderTargetCenter` (judge space x = 0..3).
  - Straight targets live in the CENTER columns — converter.js:307: `column = hand==="left" ? 1 : 2`. X slabs: straight_left [0.505,1.495], straight_right [1.505,2.495]; row-Y slabs (default 0.25 reach) cover the whole chest/shoulder band.
  - The canonical raised-fist guard pose (repo's own guard fixture → judge-world (1.26,1.06)/(1.74,1.06)) returns `pointContactsBoxingTarget = true` for **both hands on every straight cell in all three rows** (empirically executed this session).
  - **Repro (Derrick's report verbatim):** right fist STATIC at guard (1.74,1.06) while the left hand jabs → `straight_right` judges **HIT**. The credited wrist is the event's own hand — it just wasn't punching; the idle raised fist absorbed the hit. During fast alternation the orb on the idle hand's side pops at the moment the other arm swings — reads as "the wrong wrist hit it."
  - The hole is codified in tests: validate-boxing-collider-scoring.js:492-500 ("straight counts on pure overlap without any hold evidence"); judge comment "straight 100ms hold semantics do not apply" (session-coordinator.js:962). The legacy rulesets DO consume the per-hand straight hold (semantic-track :1562-1569, spatial-grid :1608-1613); the collider ruleset dropped it.
- **Ruled out (with evidence):** wrist-anchor mirroring/inversion (anatomical MediaPipe names 15/16 preserved; single (1−x) flip; CSS-only preview mirror); `measuredColliderSample` substitution (exact anchor-name lookup, no fallback); wrong-side rendering (side mapping consistent; colors follow the event hand — matches Derrick's "colored correctly"); hand-less/"any" straight events (converter always emits `${family}_${hand}`, converter.js:209/307); chord cross-attribution (strict per-hand filter); `any_punch`/`cross_body` (no judge-side consumer anywhere — content markers only, off by default for imports).
- **Fix (W3):** require the owning hand's **straight qualification** (arm extended: elbow ≥130° held 100ms — already computed per hand by the input service, body-grid-service.js:641-705) at the contact frame, restoring the legacy semantics the converter already writes onto straight events (`qualificationMs: 100, semanticQualification: "straight"`):
  - `evaluateBoxingColliderNotes` (session-coordinator.js ~988-1001): after the contact test, for `straight_*` require the hand's `straightQualifications` entry: `semanticQualified === true && measurementTimestampMs − semanticStartTimestampMs ≥ straightQualificationMs` (exact pattern of the legacy consumer :1564-1568); otherwise no candidate.
  - `boxingColliderMissDiagnostics` (~1050-1058): report the already-approved `qualification_too_short` diagnostic for an unqualified in-box hand.
  - Invert the tests that codify the bug (validate-boxing-collider-scoring.js:492-500).
  - Why not a smaller box / motion vector: a straight from a guard stance barely moves in 2D (the motion is in depth) and the guard position is *inside* the footprint — only arm extension separates a punch from an idle fist, and it is hand-strict by construction.
- **Oracle:** O1 (right fist static in the green box, left jabs → `straight_right` must MISS with `qualification_too_short` — **FAILS today: judges hit**) + O1s symmetric; O2 (genuine extension with qualification → HIT, control); O3 (left fist in green box, only LEFT qualified → still MISS — hand-strictness guard); O4 symmetric. Pure coordinator + synthetic evidence, no camera.
- **Derrick decision (open):** `semanticQualified` (extension only — **recommended**: matches `semanticQualification:"straight"` and the legacy semantic-track consumer) vs `spatialQualified` (stricter: also requires central sub-columns, the spatial-grid variant). Note: a punch whose extension completes <100ms before the contact frame now misses — same as the legacy rulesets' shipped semantics; `straightQualificationMs` stays tunable.
