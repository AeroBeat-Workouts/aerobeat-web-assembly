### Meta (recurring, Derrick): the e2e "visual proof" is not real
- **CONFIRMED.** The aftermath/vignette oracle (`validate-0.0.55-visual-proof.js`) asserts on `result.model.objects` (the **scene graph**), which is *correct even when the render is broken* — it cannot see facade-level entity pooling, shader output, or a position that only changes at draw time. **Only** `validate-exact-3c9d-browser-pixels.js` reads **real canvas pixels** (OffscreenCanvas `drawImage` + `getImageData` of the PlayCanvas canvas), and it is scoped to the 3C9D obstacle case. **Fix:** add a durable **real-pixel gameplay oracle** (extend the 3c9d pattern) that drives aftermath + boxing collision through the real renderer and asserts **rendered pixels** (both halves present at a stable x; desaturated-not-flat; red edge vignette for boxing). This is the standing requirement.

## Decisions (Derrick, unless noted)
- **B11 aftermath art:** the hit-corpse keeps the **note's actual glyph** (white outline + colored center) but **desaturated / grayed (color removed)** — *not* a flat gray blob. [Design decision to confirm — see below.]

- **B12:** boxing nose–obstacle collision must fire the **same red edge vignette** as Flow.
- **e2e:** every visual fix is proven by **real rendered-pixel** oracles, not scene-graph/unit-mock.
