## Goal

Address the 0.0.94 mobile playtest feedback: fix the Play/Pause button toggle, fix saber shadow direction/rotation, make the score/combo/multiplier HUD visible, add Good/Almost text popups, widen the responsive FOV for saber edges, extend the track Z extent for portrait, fix the pre-existing mode-change bug (equipment changes but beats don't), make boxing squat obstacles 4.5 rows tall, make boxing guard beats always spawn at the top row, and add an FPS counter to the gameplay UI.

---

## Overview

Derrick playtested 0.0.94 on desktop (Chromium, 511×935 portrait) and his mobile phone. The swept collider, scoring tiers, and HUD were implemented but several issues surfaced: the Play/Pause button shows both icons simultaneously, saber shadows rotate unpredictably, the score/combo/multiplier HUD isn't visible, only "Great" and "Miss" popups appear (no "Good"/"Almost"), saber edges are cut off at portrait, the track stops too early, the pre-existing mode-change bug is still present, boxing squat obstacles are too easy to dodge, and boxing guard beats should spawn at the top row. An FPS counter would help diagnose on-device performance.

Key decisions (confirmed with Derrick, 2026-10-06):
- **Play/Pause:** toggle — Play triangle when paused, Pause bars when playing. Never both.
- **Saber shadows:** the shadow SHOULD follow the saber's rotation (floor-projected X axis / yaw only). The current bug is that it uses the full 3D quaternion (pitch+roll), causing wild swings. Fix: project only the blade's X axis onto the floor plane.
- **Squat geometry:** 4.5 rows tall — 3 rows above the current top + the top row + 0.5 rows below. Full width (4 columns).
- **Guard beats:** always spawn at the top row (forces the athlete to raise hands into guard and push the beat back).
- **FPS counter:** add to the gameplay UI so Derrick can diagnose on-device performance.

### Task 2: Saber shadow direction fix

**Role:** `coder`
**References:** `REF-03`, `REF-04`
**Prompt:** Fix the saber floor shadow direction. The current implementation projects the saber's full 3D orientation quaternion onto the floor, which includes pitch and roll — causing the shadow to swing wildly when the hand tilts. The fix: project only the saber's **X axis** (blade direction) onto the floor plane (Y=0), giving a stable yaw-only direction. The shadow should be a flat rectangle on the floor, rotated to match the saber's floor-projected blade direction. Add a direction assertion to `validate-equipment-shadows.js` that verifies the shadow rotation matches the saber's floor-projected X axis (not the full quaternion).

**Files:** `aerobeat-web-renderer/src/gameplay-scene-model.js` (`equipmentShadowObjects`), `aerobeat-web-renderer/src/renderer-facade.js` (`equipmentShadowDirectionsForFrame`), `aerobeat-web-renderer/scripts/validate-equipment-shadows.js`.
