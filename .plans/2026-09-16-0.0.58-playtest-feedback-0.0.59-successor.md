## W0 Diagnosis

### B13 — flow corpse flat, boxing tinted (root cause)
- The **song-palette system IS applied to live notes.** `projectRenderEvents` (content-runtime.js:457) sets `appearanceColor = palette.left|right` for **every flow note**, because flow beats always carry `hand` (converter.js:325, from Beat Saber color 0/1) + a boolean `requiresDirection`. The effective palette is exactly "song 1st, AeroBeat defaults 2nd" (`createEffectivePalette`, package-content.js:500: authored palette `source:"song"`, else `defaultNotePalette` `#2693FF`/`#39C96B` `source:"aerobeat_default"`). So the **live** flow note is colored (the playtest orb is blue).
- The **corpse** desaturates `appearanceColor ?? roleColor(role)` (renderer-facade.js `aftermathCorpsePartColor`). The flow aftermath role is **hard-wired to `"neutral"`** (`AFTERMATH_FAMILY_ROLE.flow = "neutral"`, gameplay-scene-model.js:452) → `roleColor("neutral")` = `theme.receptorColor` = `#D9F5FF` (near-white). When the flow corpse's `appearanceColor` is absent, it desaturates near-white → reads flat. **Boxing** resolves its role to `left`/`right` (saturated `#2693FF`/`#39C96B`) → tinted.
- **Why the flow corpse's `appearanceColor` is absent** (to confirm with a real-pixel probe in W1): the corpse entry's `appearanceColor` is set by `eventNoteAppearance(event)` (assembly, uppercase `#RRGGBB` only) on the *event the aftermath path uses*. In **Test mode** the aftermath is built from `renderEventIndex.orderedEntries`, which may not be the palette-carrying *render* events that the live projection uses — so the live note is colored but the corpse falls to the near-white `receptorColor`. The `appearanceColor` threading into the Test-mode aftermath entry is the prime suspect (vs. the role fallback).
- **Fix (W1):** make the flow/punch corpse resolve its color from the **note's hand (left/right)** through the same system as boxing — carry the note's `appearanceColor` onto the flow aftermath entry (assembly: set the flow entry `hand` to `beat.hand`, and ensure `appearanceColor` threads in Test mode), and derive the flow/punch aftermath **role** from `entry.hand` (renderer) so the fallback is `palette[hand]` (AeroBeat default `#2693FF`/`#39C96B`), not near-white `receptorColor`. **Real-pixel proof:** a flow corpse renders desaturated to the *same* color family as its live note (not flat).

### B14 — below-track + "snap" (root cause)
- The corpse is a **closed-form (deterministic) animation, not a physics sim**: launched from the hit position with a per-family velocity, falls under gravity (9.8 WU/s²), **bounces twice off a floor plane at y = −1.17** (`gameplayWorldGrid.floorY − AFTERMATH_ICON_HALF_HEIGHT_WU` = −0.72 − 0.45), which is **~0.37 WU below the track surface (y = −0.80)**, then **settles** into a damped-tumble pose. The **"snap"** is a real discontinuity: flight tumble (4.0 rad/s) switches to a different damped-tumble formula at settle, so the rotation jumps.
- **Fix (W2, Derrick's choice):** remove the floor/bounce/settle. The corpse is launched and then just **falls under gravity until it's off-screen below the track** — no floor, no bounce, no settle, no snap, no below-track rest. This also fixes boxing corpses. (Un-evicted corpses persist off-screen/invisible until evicted — functionally the same contract.) **Real-pixel proof:** no settle discontinuity, no below-track rest; the corpse falls and exits below the track.

### B15 — boxing corpse spawn x (root cause)
- The corpse spawn = `spawnForEvent` (assembly) → for a boxing punch, `spatialTarget.targetCell` (columns 1/2) → `gridCellToWorldZ0` (x = `columnX[cell%4]`). The live note's x = `worldPositionForCell(targetCell).x` (same mapping). The playtest shows a **single-frame horizontal jump** from the note to the corpse, so the corpse's spawn x does not match the note's rendered x in practice. **To confirm the exact mismatch with a real-pixel probe in W3** (the "Incomplete" boxing chart is Derrick's library, not local — the probe will drive a real boxing punch and compare the live-note screen x vs. the corpse spawn screen x at the commit frame).
- **Fix (W3):** spawn the boxing corpse at the note's **actual rendered position** (the same x the live note occupies at the hit), not a re-derived cell that can drift. **Real-pixel proof:** at the commit frame the corpse's screen x == the note's screen x (no jump); the knock/launch then plays from there.
