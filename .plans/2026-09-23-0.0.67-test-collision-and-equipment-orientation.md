## Proposed architecture

### Real Visual Test collision

- Build a deterministic, production-shaped synthetic input/evidence frame from the retained Test wrists, timeline, and active Test session identity.
- Add an explicit gameplay-owned Visual Test interaction mode rather than broadening all `visual_test` sessions implicitly.
- When automatic feedback is off and mouse hand is selected, commit the synthetic frame and run the same Flow/Boxing live judging path used by Play.
- Keep standard judgement/score/combo/miss snapshots and renderer aftermath. Remove renderer-synthetic feedback for those events so one beat has one outcome authority.
- Reset collision histories on hand change, pointer invalidation, seek, pause/resume, fresh Test, hidden/terminal, disconnect, or source identity change to prevent teleports from becoming swept hits.

### Multi-axis orientation

- Replace scalar `rotationZDeg` base transforms with canonical `rotationEulerDeg: {x,y,z}` per hand.
- Flow keeps its existing 2D gameplay direction/zone heading for saber collision orientation and gains per-zone local XYZ visual orientation offsets so direction remains collision-authoritative while model pose can be tuned.
- Boxing states become per-state XYZ Euler targets, eased independently using the existing state tracker timing/curve and composed with per-hand base XYZ orientation.
- Renderer applies one documented quaternion composition order to GLB and fallback models; equipment records carry finite bounded XYZ values.
- Collision geometry changes only where the production detector intentionally derives orientation from these settings; any visual-only axis must be explicitly labeled to avoid violating visual-equals-hit.

### Saber glow

- Make the glow share the blade's exact root transform, local axis, scaled blade midpoint, and effective orientation. Verify GLB and primitive fallback separately at scales `1` and `2`, multiple directions, and combined XYZ rotations.
