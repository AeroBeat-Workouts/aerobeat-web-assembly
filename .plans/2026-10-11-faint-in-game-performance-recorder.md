## Diagnosis (before product edits)

### Exact observed failure

Derrick reports: “there's nothing recording this information for me to pass to you” during a real same-song Test run that reproduces the FPS dip. The page has a `Download scalar report` button, but only inside a `<details>` panel at top-right. `refresh()` closes that panel whenever Test is `playing` (`faint-hit-diagnostic.js:138–144`), and its `toggle` handler closes it again if opened during play (`:263`). The warning bar (`faint-hit-test.html:25`) takes the bottom edge and the controls instead emphasize build history (`:26–32`). Prior Playwright QA downloaded only after it invoked the app's `pause('diagnostic_export')` programmatically and conditionally opened the details, not through ordinary on-screen gameplay controls. The measured frame histograms exist in memory when eligibility holds, but the page does not tell a phone user clearly whether recording is live or how to export that run.

### Expected behavior and execution path

On the game screen, the player should see a small unobtrusive recorder with a truthful Recording/Needs setup/Paused status, a readily accessible Download JSON button, and the corpse-visual toggle. The genuine Test path remains `aero-game` → `runDisplayFrame`/`renderGameplay`/`rendererFrame`/`renderer.updateSceneObjects`; the page-owned wrappers already aggregate eligible display intervals, full frame, projection, renderer and presentation wall times, and scored hits into bounded histograms/windows. Clicking the export button must finalize or snapshot a usable run through `report()` and trigger a browser JSON download directly from a touch/click, with no hidden panel or programmatic app pause. Report coverage must explicitly mark why a run had no eligible samples. Actual Faint assets, pointer coordinates, per-note judgements, raw media and CV data must remain absent.

### Root cause and alternative hypotheses

**Confirmed UX root:** the page intentionally hides its export and controls while playing; the only prior browser proof paused through an inaccessible programmatic helper. Even though in-memory samples are captured for eligible Test frames, the phone user cannot discover or activate the export while playing. **Independent gap:** automatic feedback defaults on and/or a mouse hand may not be selected on a fresh phone; `eligibility()` then rejects samples without an obvious setup prompt. **Alternative:** browser download policy can still block a touch-initiated Blob download on a physical phone; Playwright success after programmatic pause does not settle that platform-specific unknown. **Alternative:** the exported phase aggregates may be too broad to attribute repeated group-hit stalls; require an explicit hit-linked scalar window or document limits rather than invent GPU timing.
