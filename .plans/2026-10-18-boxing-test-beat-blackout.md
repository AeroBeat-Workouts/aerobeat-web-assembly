## Debugging report (completed before product code changes)

### Exact observed failure and expectation

Derrick saw Boxing Test beats “turning black and disappearing and reappearing as [they] get past the boxing gloves” with native Show on and Scale approximately default `.5`. Our signed0.0.134 controlled Boxer Test frame at beat center20,000ms measured note center RGB `[23,82,150]` when wire crossed it; signed0.0.133 under the identical .5 volume, fixture chart, glove position and frame yielded `[33,129,239]`. At 19,900, 19,950 and 19,975ms the note stayed normal blue in **both** builds; no unexpected page errors. Direct user visual description is stronger than the measured center-pixel difference, but the same-frame wire definitely darkens the beat. The beat should stay readable blue in Test when it passes gloves; Show wire may outline the volume but should not paint the authored target dark or vanish it.

### Execution path and root cause

Native `<aero-game>` Test selection starts `visual_test`; connected real PlayCanvas GLBs and Test equipment preview resolve left-hand pose at world `(-.5,1,.45)` after its real mouse pointer projection. Assembly `rendererFrame()` sends selected Boxing chart targets and `equipmentColliderAnchors`, with Show on and Scale `.5`, Depth +`1` / −`3`. Renderer `buildGameplaySceneModel` positions the authored `directional-arrow/rounded-outline-v1` beat at `(-.5,1,z)` as its audio clock advances from t19,900→20,000ms. The translucent Boxer fill is in the pre-World gameplay collider overlay layer, **but** the new `.8`-opacity charcoal 12-edge `boxingColliderWirePool` draws in the *post-World Flow outline layer* with depth testing/writing off. At the crossing, that line overlays the blue GLB regardless of target depth, darkening the face. In signed0.0.134 the exact same frozen Test frame, disabling **only** the wire restores `[33,129,239,255]`; moving **only** its render layer to the existing pre-World collider overlay also restores `[33,129,239,255]`; restoring post-World repeats `[23,82,150,255]`. Signed0.0.133 (same Boxer fill, no wire) is `[33,129,239,255]`. This directly isolates render ordering as the cause; not a score, asset, storage or material change.

### Alternatives and uncertainty

1. Old translucent fill or alpha/depth interaction: unlikely. Fill is unchanged and wire-only disabled in new runtime matches old note pixel exactly.
2. Large saved Scale: contradicted by Derrick's answer (Show on, Scale around `.5`) and the reproduction with explicitly `.5` native setup.
3. Dark backside/asset or chart authoring: contradicted by exact same real GLB in both signed builds and wire-only same-frame control. The Test fixture supplies its own explicit normal spawn distance because synthetic content has no original chart timing authority; this is fixture setup, not a runtime change.
4. More extensive blackouts at other timing/poses: plausible; user did not provide a captured video, exact chart, physical tracking position or frame times. The reproduced stroke-darkening is an in-scope cause with a clear fix, but visual feel must be judged by Derrick on a phone.

### Why previous tests missed it

The 0.0.134 checks covered static scored **Play** Boxer Show on/off and isolated wire-only contrast, but had **no Boxer Test note-through-glove temporal state**. Flow Test used Flow's different capsule and saber asset. An initial synthetic Test attempt showed no notes because the fixture intentionally had no timing authority; an explicit valid fixture spawn distance exposed the beat. A synthetic Test transport seek discarded in-flight targets as intended, so the actual advancing `runDisplayFrame()` / audio clock was used instead. These were fixture setup failures, not alternate product fixes.
