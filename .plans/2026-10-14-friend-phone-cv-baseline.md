## Decision and scope

The valid 60-second Derrick-only control: 640×480/30 configured, 29.883 distinct video-element media times/s, 8.333 fresh CPU-WASM MediaPipe Pose Landmarker Lite Worker poses/s, 70.4/81.4ms Worker inference p50/p95, 71.7/82.8ms roundtrip, 396/896 in-flight busy drops (44.2%). The adapter overhead is small, so inference is the immediate limit. This single phone cannot identify chip speed versus browser/WASM/SIMD, thermal throttling, lighting or capture conditions; the full Play scene added contention in the earlier 6.883/s report. Compare other phones under the **same build stamp/camera/Worker/15/s policy**. Do not change CV delegate, model, rate, camera constraints or scoring for this comparison. Investigate a GPU-delegate A/B as a separate opt-in follow-up only if phone samples warrant it.

Derrick wants **one link to an HTML test page**, not a literal offline single-file MediaPipe runtime. The already-built `phone-cv-marker-baseline.html` is independent of the game and is the comparable page. Its pinned Worker, model and three WASM variants total about 40 MB across twelve built static assets; compressing or embedding everything into one huge HTML changes startup/memory behavior and may bias phone measurements. Keep the exact signed c67b1e5 build unchanged, copy the complete verified static bundle (including its SHA sidecar) to a distinct immutable local snapshot, and run a separate loopback-only preview server on port 4195. Do not repoint or interrupt private localhost4194/Tailnet HTTPS8455, Play8454 or older services. If a public link is approved, use Tailscale Funnel HTTPS port **10000** to the new localhost4195 snapshot: Tailscale supports public 443/8443/10000 only, not arbitrary 8456. No `funnel reset`, no public path to repo/dev server/DSH GUI and no additional output or uploads. See [official Funnel port and public/Serve separation rules](https://tailscale.com/kb/1223/funnel).

The browser camera requires HTTPS and a user permission grant. All measurement stays local until the friend taps Download JSON and voluntarily shares the bounded aggregate file; no frames, pixels, pose landmarks, device IDs, identifiers, uploads, analytics or public iframe messages. The report intentionally omits phone identity, so ask each friend to separately state phone model, OS/browser and whether low-power mode was on when sending a report. If friend-facing UX wording needs change, do it in a **separate** build and test before publication; never silently relabel or change the signed measurement artifact. `?preview=1` is synthetic QA only and always invalid as physical evidence. A normal valid 3s warmup +60s report must have `report.valid` and `window.valid` true, same build stamp, nonzero real CV/marker counts and no camera/CV/calibration interruption.
