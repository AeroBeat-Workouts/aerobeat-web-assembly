## Section A — Single-song Reimport, then same-hand minimum interval

- **A1: selected-song Reimport** (`gmnl.2`; Assembly + UI + authoring persistence). Put a `Reimport` button immediately beside `Reimport All` in Downloaded songs; target exactly the selected song and original BeatSaver version via private collection provenance, not a user-supplied URL or the presentation-only summary. Reuse the existing import-progress/error surface; any new visible progress or failure copy needs separate wording approval. Never delete the existing selected collection before downloading and validating the replacement; stage and commit its replacement safely, keep the old one available if reimport fails, avoid duplicate songs, and leave unrelated songs untouched. Test with isolated fixture collections; do not invoke current `reimportAllLibraryCollections` against Derrick's real library because it deletes first. Handle unsupported source collections without initiating a broken operation; obtain approval before displaying any new explanation.
- **A2: same-hand spacing** (`gmnl.3`; authoring + Assembly Game Setup + UI controls). Expose `Minimum time between same-hand Boxing punches (ms)` in Game Setup/pause, as a nonnegative integer (proposed 0–2000 ms, default 0). Apply it at import to the *emitted* Boxing punch timeline per hand, alongside the existing global `punchMinSpacingMs` and spacing optimizer, not to Flow or cross-hand pairs. Guard and obstacle behavior remains unchanged in this section. Keep conversion deterministic and trace any dropped/reassigned source event. Changing an already selected chart alone must not pretend it regenerated every stored difficulty; whether any explicit Reimport instruction appears in the UI is pending Derrick's copy review.
- **A acceptance:** 0 ms preserves existing output; synthetic adjacent left-left notes respect the chosen gap while left-right notes are not unnecessarily removed; real selected-song BeatSaver conversion is repeatable after Reimport and a new Play/Test uses the newly authored chart. Test affected authoring/worker, persistence replacement and Game Setup/UI boundaries, then one private connected game in direct and iframe. Derrick tests comfort and picks a value; **only a later build** freezes it and hides the setting at his request.

## Section B — Reduce repetitive Boxing patterns

- **B1: family-preserving hand alternation** (`gmnl.4`; authoring + Assembly). Add one visible integer `Repeated-punch alternation chance (%)` in Game Setup/pause, 0–100, default 0 and reimport-required. For *consecutive same-hand punches of the same family*, deterministically seeded decisions may flip the later punch to the opposite hand while retaining its straight/hook/uppercut family. Recompute lane/target/direction, event IDs, lineage, optimizer eligibility and traces; do not merely relabel a left-hand collision as right-hand. No post-import randomness, no changes to Flow. Treat existing source guards separately.
- **B2: repeated guards** (same Bead). When a run of guards is encountered, the same tuning chance may replace a guard with one seeded straight, hook, or uppercut, assigning a feasible hand/lowest-risk target rather than spawning multiple simultaneous punches. This proposed *shared chance* avoids adding a second unrequested menu dial; it couples guard variation to hand variation, so separate them later if Derrick finds the effects need independent tuning. Respect Section A spacing, obstacles, timing windows, score semantics and source provenance. Keep 0% behavior unchanged.
- **B acceptance:** fixture charts prove 0% baseline, 100% rule applicability, intermediate seeded repeatability and retained valid hit targets for all three punch families; guard replacement never violates spacing or obstacle reach. Reimport one selected song, visually inspect authoring trace and test real Boxer Play/Test scoring without multiplying hit events. Derrick playtests strain and repetition before any later lock-in.

## Section D — Knee version, tracking, controls, and real hit

- **D1: two charts per Boxing difficulty** (`gmnl.6`; authoring/worker, package contracts, content runtime, Assembly). Every newly converted BeatSaver difficulty authors both `knee` and `no-knee` Boxing variants while sharing the same source and audio, not duplicating a downloaded song. Add `Knee strike chance (%)`, integer 0–100, import-time setting. On the knee variant only, seeded guard replacements yield one `knee_left` or `knee_right` beat in the **lowest row**, alternating legs on emitted knee beats, starting left. The no-knee chart keeps guards. The existing Boxing selection gets a default-ON `Enable knee strikes` switch that selects the already-authored knee/no-knee variant for the next Play/Test start; changing the chance requires selected-song Reimport. Define compatible legacy-package behavior explicitly (prefer selecting their no-knee chart until reimport), with truthful UI. Run count, lineage, source/payload hash and chart-ID checks across both choices.
- **D2: knee gameplay and pose** (same Bead; CV adapter, input/contract, gameplay, renderer, Assembly + Game Setup/Test UI). Extend today's seven-landmark pose path to include visible MediaPipe left/right knees (and only the hip/ankle evidence required for a stable lift angle); **do not change T-pose calibration** or Flow visibility. Show two yellow knee marker dots when the respective landmark is visible in enabled Boxing; never retain stale marker/pad pose across tracking loss. Attach left/right color-matched pads to tracked knee anchors, facing oncoming beats. Add Boxing-only knee collider `Show volume`, `Scale`, `Depth +`, `Depth −` to gameplay/pause like gloves, and knee-height-based pad rotation tuning to Test. Judge only the matching knee collider at the lowest-row target, respect normal time windows and contact lifecycle, keep knee beats out of hand scoring and avoid double hits. Hide markers, pads and collider overlays whenever Flow or no-knee Boxing is active, regardless of stale frame state.
- **D acceptance:** both chart versions load and select without recompiling; 0% and 100% seeded guard replacement/left-right alternation pass; matching-side visible tracked knee yields one scored hit; invisible, wrong-side or no-knee variants yield no knee collision; Flow remains unchanged and T-pose still uses the original calibration. Native direct/iframe Boxer Test + scored Play show the canonical target and colored pads (including lowest-row and tracking-loss states). Then Derrick tunes the chance, collision depth and rotation with a physical camera/leg playtest; automated pose fixtures cannot prove ergonomic safety.
