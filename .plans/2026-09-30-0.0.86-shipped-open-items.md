## Shipped in 0.0.86

- **Variant-swap hard-lock** (third report from Derrick). Root cause: content's
  future swap publishes a deliberately MIXED snapshot and that state persists;
  the assembly filtered it only when the caller passed `futureOnly=true`, so
  pressing Play/Test after a paused mode switch fed outgoing Flow events into
  gameplay's strict validator. Fix: unconditional filter with a deliberate
  fall-through, so a genuinely inconsistent snapshot still fails loudly instead
  of degrading to an empty chart. Covered by
  `scripts/validate-mode-switch-after-complete.js` (wired into `test:unit`),
  proven to fail without the fix.
- **Guard spacing 0.25 reaches existing users.** The source default was already
  0.25; persisted setups kept the old stored 1.0 forever. One-shot,
  marker-backed migration of that legacy sentinel only.
- **Obstacles fieldset removed** from the Flow selector, plus four browser-test
  expectations rebuilt against the real post-removal UI.
- **Expert Plus difficulty dot** black instead of `#8000ff` purple.
- **Fullscreen + calibration icon buttons** beside the volume control in the
  transport; both removed from the gameplay/pause menu.

## Two questions answered with evidence, awaiting Derrick's call

### Straight punches in their own handiness lane

The blocker is NOT the crossing itself. 0.0.83 moved every straight to row 0.
`uppercut_left` already occupies cell 1 (row 0, left column), so an own-lane
`straight_left` wants the same cell and is dropped as `spatial_target_blocked`.
Crossing survives only because it puts straights in the free column. Recommended
fix: relocate a blocked note instead of dropping it (the converter already has
relocation machinery). Do not simply restore crossing.

### Boxing obstacles rendering as full-screen walls

The lean/squat system Derrick remembers IS implemented: `targetPositions` in
`aerobeat-web-renderer/src/gameplay-scene-model.js` renders 2 lanes for a squat
and 1 lane for a weave. What breaks it is `aerobeat-web-content-authoring/src/beatmap.js`:

```js
if (kind === "v2_type_0" || kind === "v2_type_1") {
  gameplayY = 0; gameplayHeight = 3;   // forced full height, always
}
```

Every v2 obstacle is forced to 3 rows tall regardless of its real rectangle, so
the lane system receives geometry covering the whole play area. v3 is fine — a
canonical squat `{x:0,y:2,w:4,h:1}` derives to top-row-only. Likely fix: make v2
derive from its actual rectangle the way v3 does.
