## Root Cause — confirmed in a bounded traced reproduction
`/tmp/aerobeat-flow-centerline-phone-scene-call-trace-1.log:11-20` reproduced the **same** real-iframe `4 !== 0` failure with scene-call tracing. The cleanup `runDisplayFrame()` **did invoke** `renderer.updateSceneObjects` once with four model aftermath pieces, but both immediate and delayed pool counts were four. The gameplay session was `paused_manual`, `pauseReason: "audio_clock_rollback"`; audio was paused at exactly 4.0 seconds, while the off checkbox remained checked, Automatic Feedback was OFF, hand left, and CV idle. No later redraw was needed. The original cleanup bug is in the **test-only negative control's second `await audio.seek(4); await audio.play()`**. A later remote iframe run and same-test counterfactual showed its **first** literal `seek(4)` has the same defect if the previous scored group timeline is already slightly beyond 4s; both seeks must preserve monotonic scored time. The mutant frame had just advanced gameplay's monotonic audio timeline to approximately 4.01 seconds. Seeking the audio *backward* to 4.0 before the cleanup frame satisfies the production session-coordinator's rollback guard (`aerobeat-web-gameplay/src/session-coordinator.js:408-412`), which correctly pauses Test. The reporter filters only eligible **playing** scored Test display frames (`flow-centerline-diagnostic.js:125-149,240-245`); after the fixture-induced pause it intentionally forwards the native four-piece scene and cannot clear the deliberately leaked pool. Parent GREEN and independent QA RED are explained by whether the first mutant frame read exactly 4.0 or slightly later audio time before the second 4.0 seek. The real application behavior is correct; fixture repeatability was false.

The smallest fix is to restore `renderer.updateSceneObjects` and call the cleanup `element.runDisplayFrame()` **immediately without a second seek/play**; the audio clock already plays and remains monotonic after the mutant frame. Explicitly assert `session.state==='playing'` before/after that cleanup and both immediate and delayed pool0; retain mutant frame's >=3000 gray-pixel RED proof, actual off-frame <=1000 GREEN proof, restored/native first/group pixels and exact downloaded JSON in both embeddings. No production scoring or reporter eligibility change.

## Alternative hypotheses and disproof
- **Song simply ended.** A controlled 21-second audio-end stress yielded `completed`, scene model0 and pool0, not the observed `paused_manual`/model4/pool4. Not this failure.
- **A later non-RAF redraw reenabled entities between Playwright evaluations.** The red trace found **immediate pool4 and delayed pool4**, with a single cleanup scene call in the paused session. There was no required later native redraw.
- **Renderer pool-reset bug or lost reporter wrapper.** Real off frames cleared the same pools, and the red cleanup call was observed with a restored wrapper; it forwarded native only because the fixture's backward seek put gameplay into its intentional rollback pause. No production renderer/wrapper bug demonstrated.
