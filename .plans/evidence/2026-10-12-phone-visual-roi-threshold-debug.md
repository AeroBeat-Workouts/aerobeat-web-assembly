# First v3 preview E2E: corpse pixel threshold and screenshot occlusion

## Exact observed failure
The first built-source browser QA (`npm run test:flow-centerline-phone-browser`, assembly commit `4fb5e8d`, build stamp `FLOW-CENTERLINE-EXPERIMENTAL-0.0.128-ddda613d9564f46fc945bbd1`) passed local/served hashes of HTML **and all seven JS**, imported a chart through the actual conversion worker, started scored Test, and reached direct/native real-framebuffer assertions. It then failed at `scripts/validate-flow-centerline-phone-browser.js:160`: `direct/native: actual GLB corpse face 2686` versus the hard-coded >=4,000 gray-pixel threshold. This did **not** reach off/restored/iframe or JSON checks; no phone timing verdict or private route change is justified. Log `/tmp/aerobeat-flow-centerline-phone-browser-qa.log:9-17`.

The saved Playwright `locator('canvas').screenshot()` at `.tmp/flow-centerline-phone-visual/<buildStamp>/direct-native.png` shows menu/panel/diagnostic HTML overlays composited on top of the canvas and a giant clipped green object at the right, even though the code's framebuffer metrics call `ctx.drawImage(canvas)` and bypass DOM overlays. Thus that screenshot is **not valid unobscured actual-canvas visual evidence**; the GLB pixel metrics are from a different, unoccluded source.

## Expected behavior
The tester's scored native + restored frames must show the new fixed-centerline real GLB corpses; corpse-off must remove only their visual pixels while preserving Great, live targets, sky, track, saber and the same score. Direct and real cross-origin iframe must prove this on actual renderer pixels with explicit localized negative control. PNG evidence should show what the oracle measures, not an HTML overlay.

## Execution path
The browser QA loads an isolated clean Vite preview, hashes built/served HTML+JS, imports a short chart/audio via real authoring worker, starts Test and disables automatic feedback and camera. Its `tick` seeks audio and calls `element.runDisplayFrame()`, then `capture()` calls `element.renderGameplay()`, copies the real game canvas into an offscreen canvas, and returns pixel arrays and scene-model/score facts for miss, hit, and two-note group. It chooses a fixed screen-space face ROI `[x0..140,y405..490]`, counts gray pixels (each RGB 90..150 with channel spread <35), and requires >=4,000 for native/restored, <=700 for corpse-off. `modelHalves>=2`, Great, live icon, saber, environment and score assertions passed before the gray threshold. The script separately uses Playwright `canvas.screenshot()` for a PNG, which captures DOM overlays composited over the element instead of the raw pixels used by the test.

## Most likely root cause (hypothesis)
The *guessed* >=4,000 gray-pixel threshold is not calibrated to the actual current portrait chart/position and fixed-centerline mask. A single native hit has 2,686 gray pixels in the ROI; unknown group and off counts should be measured to distinguish an overly high threshold from an off-mode leak or too-narrow/misplaced ROI. The screenshot overlay is a separate capture-method error: the screenshot source is the DOM compositor, not the offscreen raw canvas used by the oracle.

## Alternative hypotheses
1. **Actual half visually missing/clipped or test contact off-center:** plausible; native gray=2,686 could reflect only one half, wrong ROI, depth occlusion or current GLB geometry, especially with a giant green object in the composited screenshot. Inspect *actual raw-canvas PNGs and sign-specific rendered pool state* before adjusting thresholds.
2. **Gray predicate misses colored authored outlines:** plausible; mask keeps desaturated fill plus white outline, so many real corpse pixels are outside [90,150] even though visible. Compare hit-minus-miss or native/off baseline-diffed pixels, not only gray count, and ensure same subject/local ROI.
3. **Background/game setup occlusion contaminates the pixel array:** unlikely because `ctx.drawImage(canvas)` copies canvas pixels and does not composite DOM overlays. The Playwright screenshot does not validate this; raw-canvas PNG would.
4. **GPU/RAF cadence:** unlikely to explain a deterministic fixed seeker-frame ROI with positive score and scene metadata; still possible if `renderGameplay` and async audio drift before capture, so log time/pose if needed.

Its threshold was written from expectation rather than measured native/off screenshots. Hash writer fixes ensured build integrity but do not calibrate scene pixels.

## Crucial calibration finding: the test itself bypassed corpse-off
An explicitly **diagnostic-only, intentionally nonpassing** run logged identical direct/native, off, and restored raw-canvas SHA/pixel statistics: face ROI `[2960,807]`, broader ROIs `[4150,4680]`, `[3966,4600]`, `[3446,4256]`, active pooled halves `2/4` for all modes. The raw off hit PNG's SHA matches the native hit PNG exactly. The off checkbox was checked but the previous `capture()` helper called `element.renderGameplay()` **after** the scored `element.runDisplayFrame()` on every snapshot. Source `flow-centerline-diagnostic.js:240-244` deliberately filters corpse scene objects **only when** `samplingRaf` is true inside the actual RAF/display-frame pipeline and the session is a real Test; out-of-band `renderGameplay()` is required to forward native scene input even if off is checked (to preserve Play/noneligible semantics). Thus each out-of-band capture reinstalled corpse GLB pools after the correct off display frame and overwrote its pixels with native visuals before `ctx.drawImage`. This is a test-fixture sampling error, not yet a demonstrated production off-mode failure. The broad ROI count cannot be used as a native/off threshold until the fixture captures the **already rendered RAF canvas directly** without re-rendering. Remove the extra `element.renderGameplay()` from `capture()` and rerun explicitly nonpassing calibration, then inspect true native/off/restored PNGs and counts. If `runDisplayFrame()` fails to render directly, diagnose that separately instead of reintroducing the bypass.

## Actual RAF-canvas calibration result (not a QA pass)
With **only** the fixture's extra `renderGameplay()` removed and the same already-running built app, direct/native first/group gray counts were 2,960/807 in the narrow ROI and **4,150/4,680** in a wider subject ROI `[x0..220,y335..555]`, active pools 2/4. Direct/off first/group were 437/527 narrow and **512/574** wider, active pools 0/0, despite the scene model deliberately still containing 2/4 aftermath objects and score counts 1/3 unchanged. The raw off-hit PNG visibly retains Great, colored live notes, sky and track while removing only the grey semicircular corpses; it is not a compositor overlay screenshot. This proves the production off filter works during the actual display frame and the prior equal pixels were introduced entirely by the test's extra out-of-band render. The old narrow ROI cannot require 4,000 for group; a wide ROI can require >=3,000 native/restored and <=1,000 off with measured margins >1,000 and >400 pixels respectively. Restored and genuine cross-origin modes **exactly match**: native/restored `[4150,4680]`, off `[512,574]` in the broad ROI; pooled halves native/restored `2/4`, off `0/0`, scene model `2/4` and scored hits `1/3` unchanged, as the intentionally nonpassing log `/tmp/aerobeat-flow-centerline-phone-raf-canvas-calibration.log:5-18` shows. Change test thresholds to a measured native/restored >=3,000 and off <=1,000 in this ROI, and make the same-RAF one-frame leak control fail off. Diagnostic-only bypass must be removed before any claimed green gate or commit.
